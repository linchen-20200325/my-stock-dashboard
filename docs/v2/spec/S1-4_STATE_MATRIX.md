### 1.2.2 ⭐ `N/A`（unwired）與「未載入」（idle）同時成立時，**N/A 贏**

> **2026-09-14 v2 新增**（紅隊 §2.10 指出本組全篇漏寫；本組重驗成立）。

**實測**（`shared/ui_state.py:199–202`，判定順序）：

```
199:     if not wired:
200:         return UI_UNWIRED      ← 先判
201:     if not requested:
202:         return UI_IDLE         ← 後判
```

⇒ **一盞 `wired=False` 的燈，在冷啟動（`requested=False`）時顯示的是 ⛔ 未接線，不是 ⬜ 尚未載入。**

**為什麼這一條非寫不可**：冷啟動是**最常見的畫面**，而一個沒讀過 code 的實作者
很可能直覺地寫「冷啟動 → 全部畫 ⬜」—— 那會**蓋掉所有 unwired 燈的真相**，
把「刻意沒接、永遠不會亮」說成「還沒載入、按一下就有」。
使用者會去按、會回報「抓不到」，而它永遠不會亮 —— **那是 §5 R-2 的變體**。

**推論到清單上的位置**：`unwired` 是**閘門**，不是與 Normal／Empty／Missing 平行的並列項。
這也是為什麼「未載入」不適合被塞進母法那張平面清單的第 6 格（§1.2 但書 (ii)）。

**一句話給實作者**：**先問「這一格接線了嗎」，再問「這一輪叫過了嗎」。順序不可顛倒。**

### 1.2.1 Partial 這一格的特別處置（**最容易寫錯的一格**）

**實測事實**：底層七態**沒有**一個態叫 Partial。`UI_DEGRADED` 的定義是
「有值、可讀，但**門檻已失去判別力**」（`shared/ui_state.py:100–101`），
**不是**「部分欄位有、部分沒有」。

母法的 Partial 在本 repo 對應**兩種完全不同的情況**，處置也不同：

| | **Partial-A｜涵蓋不全** | **Partial-B｜門檻失準** |
|---|---|---|
| 意思 | 值算出來了，但**不是用全部成分算的**（例：12 檔持股只有 10 檔有匯率） | 值是全的，但**這條門檻現在沒有判別力** |
| 底層態 | `UI_LIVE` ＋ 元件自己算的涵蓋率 | `UI_DEGRADED` |
| 有沒有 enum 撐 | 🔴 **沒有** —— 必須由元件自行計算並顯式帶出 | ✅ 有（`UI_DEGRADED`） |
| 數值怎麼標 | 值後加 `*`，並在 `Note` 講明「N/M 計入、缺的是哪幾筆」 | 值照給，狀態 chip 出「門檻已失準」 |
| 燈號頻道 | 照出（那是真實觀測） | **看載什麼**：載 band/level 觀測 → 照出；載 pass/fail **判決語 → 留白** |
| 文案來源 | 元件自訂，但**必須列出缺的是哪幾筆**（不得只說「部分資料」） | `DangerSpec.degraded_reason`（`shared/macro_buckets.py:232`，`discriminative=False` 時**必填**，有測試守衛） |

**Partial-B 燈號頻道那條判準是實測既有裁定**，原文在 `src/ui/views/_ui_kit.py:240–256`
（2026-09-07 獨立稽核裁定）：

> 載 **band / level 觀測** →「照出」；載 **判決語**（pass/fail 的結論）→「留白」。
> 對一個**已知失準**的數字下「過關」判決，就是 §1「錯誤的數字比沒有數字更危險」講的失準值冒充過關。

⚠️ **Partial-A 是本 repo 目前的空白**：⚠️【單組窮舉，未經第二組複驗】本組在
`shared/ui_state.py` / `shared/station_specs.py` / `shared/macro_buckets.py` 三個 L0 模型裡
**沒有找到**任何「涵蓋率 / N-of-M」欄位。若 UI 要出 Partial-A，
**必須由上游 L3 顯式提供分子與分母**，不得由 UI 層自己數（UI 層數不到「應該有幾筆」）。

### 1.5 ⭐ `UI_IDLE` 與 `UI_UNWIRED` 的文案規則（客戶指定本組定案）

客戶已明確指出風險：**兩者呈現層都走灰色，若說明文字相同，就是把「刻意沒接」說成「不適用」，那是假話。**

#### 定案規則（三條，缺一不可）

**規則 1｜glyph 必須不同，且只由 L0 供給一次。**
`UI_IDLE` = `⬜`，`UI_UNWIRED` = `⛔`（`shared/ui_state.py:114,119`）。
`shared/ui_state.py:112` 原文：「**灰的四個狀態必須靠 glyph 分辨**」。
⛔ 文案裡**不得再自帶 glyph** —— `tab_today.Note.__post_init__`（`src/ui/tabs/tab_today.py:196–215`）
會直接 `raise ValueError`，理由原文：「兩個 glyph 就是兩個互相矛盾的說法」。

**規則 2｜三要素（`now` / `why` / `where`）三格全部不同。**
`Note` 強制三要素齊備（`tab_today.py:189–215`），本組定下的分工如下：

| | **`UI_IDLE`（尚未載入）** | **`UI_UNWIRED`（未接線）** |
|---|---|---|
| **`now`<br>現在怎樣** | 「**尚未載入**（還沒有人去取這份資料）」 | 「**這盞燈沒有在運作**（決策端刻意未接線）」 |

## §2. 數值呈現規則（母法釘死，不得改）

> 母法原文三條：
> `0.00` ＝ **正常有效數值**（正常文字色）｜`N/A` ＝ 不適用（灰字）｜`—` ＝ 缺漏（灰字 ＋ **琥珀色警示圖示**）
> **三者不可混。**

### 2.1 為什麼這三個非分不可（一句話）

| | 這個數字**存不存在**？ | 它**該不該存在**？ | 使用者該做什麼 |
|---|---|---|---|
| `0.00` | **存在**，而且就是 0 | 該 | **採信它** —— 零是一個觀測值 |
| `N/A` | 不存在 | **本來就不該存在** | **什麼都不用做** —— 這個概念對這個標的不適用 |
| `—` | 不存在 | **該存在，但這次沒拿到** | **看旁邊的說明** —— 決定要不要重抓／回報 |

**把 `—` 寫成 `0.00`** ⇒ 使用者拿一個不存在的觀測去做決策（憲法 §1 最核心的禁令）。
**把 `—` 寫成 `N/A`** ⇒ 使用者以為這是設計如此，**永遠不會去修**。
**把 `N/A` 寫成 `—`** ⇒ 畫面長期掛著一排琥珀警示，真正的缺漏被淹沒（假警報稀釋真警報，§1.A 第 4 條）。

### 2.2 可判定的規則（決策樹，照順序問）

寫 UI 的人對**每一個要印出來的數字格**，依序回答：

```
Q1 ─ 這個標的／這張表，「結構上」有沒有這個概念？
      │
      ├─ 沒有（ETF 沒有本益比、台幣基金沒有匯率位階、不配息標的沒有殖利率）
      │   └─▶ 【N/A】 灰字，**不加任何圖示**
      │        底層：UI_UNWIRED 或 reason=MISS_NOT_APPLICABLE
      │        ⚠️ 這一格**與這一輪抓得到抓不到無關** —— 抓一百次也一樣
      │
      └─ 有 ─▶ Q2
Q2 ─ 這一輪，上游有沒有給回一個值？
      │
      ├─ 沒給 ─▶ 【—】 灰字 ＋ ⚠︎ 琥珀色警示圖示
      │            底層：UI_EMPTY / UI_FAILED
      │            ⛔ **必附 reason** —— 沒有 reason 的 `—` 等於「不知道為什麼沒有」，
      │               那是把診斷責任丟給使用者
      │
      └─ 有給 ─▶ Q3
Q3 ─ 這個值通過範圍守衛（§3.2 valid_min/max）了嗎？
      │
      ├─ 沒通過（out_of_range，量綱漂移） ─▶ 【—】＋ ⚠︎，且**狀態升紅** UI_FAILED
      │            ⚠️ **不准印那個數字** —— 它看起來正常（`^TNX` 回 46.3 而非 4.63），
      │               印出來比沒有更危險
      │
      └─ 通過 ─▶ 【照實印】正常文字色
                   值剛好是 0 → 印 `0.00`，**與其他有效值同色同格式**
```

### 2.2.1 ⭐ 字面陷阱：上游回的字串 `"N/A"` **不是**呈現層的 `N/A`

> **2026-09-14 v2 新增**（紅隊 §2.7 指出；本組重驗成立，且本組 v1 確實引用了同一段 code 的結論卻沒攔下字面）。

**實測**（`src/ui/views/page_inspect.py:1058–1060`，逐字）：

```
1058: #: L3 用來表達「這一格算不出來」的字面。`"N/A"` 是 L3 明文寫的
1059: #: （`Status: "N/A" if _bad_om else ...`）；`""` / `None` 是欄位根本不存在。
1060: _MISSING_STATUSES: frozenset[str] = frozenset({"", "N/A", "None", "none"})
```

⇒ **L3 的 `"N/A"` ＝「算不出來」，被歸成 `empty`** —— 也就是本文件 §2.2 的 **`—` 那一桶**，
**不是** `N/A` 那一桶。同檔 `:1152` 邊界 (d)：「某一格的 Status 是 `N/A` → **只有那一格** `empty`」。

**照 §2.2 決策樹直覺實作會怎麼錯**：看到 L3 回 `Status="N/A"` → 直接印灰字 `N/A`、不加 ⚠︎
→ 使用者讀到的是「這個概念本來就不該有」——
**那正是 §2.1 自己寫的「把 `—` 寫成 `N/A` ⇒ 使用者以為這是設計如此，永遠不會去修」。**

#### 轉換規則（寫死）

> **⛔ 任何上游字串都不得直接當呈現層的符號。呈現層的 `0.00` / `N/A` / `—` 一律由 §2.2 決策樹產生。**

| 上游給的 | 它的意思 | 呈現層應印 |
|---|---|---|
| `"N/A"`（來自 `_MISSING_STATUSES` 族的 L3 欄位） | **算不出來** | **`—` ＋ ⚠︎** |
| `""` / `None` / `"None"` / `"none"` | 欄位根本不存在 | **`—` ＋ ⚠︎**（⚠️ 見下方但書） |
| 真正的「結構上不適用」 | 這個概念對這個標的不存在 | **`N/A`**（灰，不加 ⚠︎） |

⚠️ **但書：「欄位根本不存在」有兩種，必須再問一次。**
「欄位不存在」可能是 **(a) L3 這一輪沒給**（→ `—`），也可能是 **(b) 這個判型結構上就沒有這一欄**（→ `N/A`）。
**分不出來時一律走 `—`** —— 理由：`—` 的錯誤方向是「多叫一次修」，`N/A` 的錯誤方向是「永遠沒人修」（§2.1）。
**從嚴。**

⚠️ **這條規則適用於所有上游字面**，不只 `"N/A"`：
`"無資料"` / `"—"` / `"-"` / `"null"` 從上游來的時候，**都只是資料，不是呈現決定**。

#### 3.1.1 ⭐ 那個 `—` / `N/A` 到底放哪？（**未決的架構問題，不是填表題**）

> **2026-09-14 v2 新增。** 這是 v1 最嚴重的錯誤所暴露出來的**真問題**：
> **母法線框要它出現在大字區，而現行 L5 契約禁止。** v1 直接照線框寫，會 `raise`。

**衝突的兩端（都是實測）**：

| 一端 | 內容 |
|---|---|
| **母法線框** | 卡片畫的是 `│ 【N/A】     │` ／ `│ 【—】       │` —— placeholder **就在大字數值位置**（S1-3 §1.3 表；⚠️ 本組**未複驗** S1-3，僅轉錄其圖示） |
| **現行 L5 契約** | `src/ui/tabs/tab_today.py:229–240`：`value` 欄註解「**正常態才准有的結論文字。非 `live` 一律為空**」；`:237` `if self.state != UI_LIVE and self.value: raise ValueError(...「只有 live 能給結論（線框 §02：只有這一態能給結論文字）」)` |

**四條路，代價不同**：

| 路 | 做法 | 代價 | 分層後果 |
|---|---|---|---|
| **(a)** | placeholder 放 `facts` 的第一列（如 Partial-B 現行做法） | **零契約變更、今天就能做** | 無 —— 但**視覺上與線框不同**（placeholder 不在大字位置，字級小很多） |
| **(b)** | 放寬 `Card.__post_init__`：非 live 允許 `value` 落在**白名單** `{"—", "N/A"}` | 改 L5 dataclass 守衛 | 守衛的**目的**（「只有 live 能給**結論**」）其實沒被破壞 —— `—` 不是結論。但白名單會隨時間被加東西 |
| **(c)** | 新增 `Card.placeholder: str = ""` 欄位，與 `value` 分開 | 改 L5 dataclass **結構** | **語意最乾淨**：`value`＝結論、`placeholder`＝缺席標記，守衛一字不動 |
| **(d)** | 當成畫面結構問題送客戶拍板 | 一輪往返 | —— |

**★ 本組推薦：(c)，理由三條**（依 v3 §03-2 請示規範，附推薦不只丟選項）：
1. **它保住守衛的原意**：`value` 繼續只表示「結論」，`:237` 那行**一個字都不用改** ——
   而那行守衛擋的是一個真實的失效模式（非 live 卻給結論），不該為了 placeholder 把它挖鬆。
2. **(b) 的白名單會長大**。今天放 `—` 和 `N/A`，明天有人想放 `--` 或 `N.A.`，
   守衛就從「擋結論」退化成「擋沒登記的字串」。
3. **(a) 雖然零成本，但會讓每一張非 live 的卡都矮一截**，卡片高度不一致；
   且 placeholder 掉到 caption 級字體，**`⚠︎` 在餘光裡會看不見** —— 那正是 §2.3 C 要保住的唯一視覺差。

**⚠️ 這是「怎麼做」不是「做什麼」** —— 依 `CLAUDE.md §-1.5 A-4`，
「資料結構怎麼切、欄位怎麼加」屬**技術實作層，內部拍板，不請示客戶**；
但依 §8.1，**動 L5 dataclass 前必須先做架構踩點**（六點答完才准寫 code），
且依 §-1.5 第四條**必須寫進交付報告**。
**(d) 不是必要的** —— 線框已經畫過了，讓 placeholder 真的出現在大字位置是**實現既有線框**，不是改設計。

⛔ **在 (a)(b)(c) 任一條落地之前，實作組一律走 (a)** ——
因為那是唯一今天不會 `raise` 的路。**絕對不要把 placeholder 塞進 `card.value` 試試看。**

#### 3.3.4 ⭐ 「整表不畫」vs「逐列保留」的判準（**v1 缺，兩節會給出相反指令**）

> **2026-09-14 v2 新增**（紅隊壓測情境 (b) 打出來的缺口；本組接受）。

**問題**：§3.3.2 Error 行說「**不畫表**」，§3.5 Error 行說「**列保留，不得消失**」。
同一批個股資料抓失敗時，實作者會拿到兩條相反的指令。

**判準（一句話）**：**問「我知不知道應該有幾列」。**

| 情況 | 知道應有幾列嗎 | 做法 | 為什麼 |
|---|---|---|---|
| **整表級失敗**：查詢／清單本身沒跑成功（連「有哪些標的」都不知道） | ❌ **不知道** | **不畫表**，畫 `Note` ＋ 錯誤 | 畫表頭 ＋ 0 列會被讀成「查過了，就是沒有」—— **那是假話**（§3.3.2 原文） |
| **逐列失敗**：清單拿到了（知道有 12 檔），其中 3 檔的資料抓失敗 | ✅ **知道** | **全部 12 列都畫**，失敗的 3 列各格 `⚠︎ —` ＋ 列首紅標記 | 刪掉那 3 列 ⇒ 使用者**不知道有第 11、12 檔**（§3.5 原文） |

**⭐ 推論**：**「有沒有拿到標的清單」是分水嶺。**
- 清單沒拿到 → 整表級（§3.3.2）
- 清單拿到了、內容沒拿到 → 逐列級（§3.5）

⚠️ **最容易錯的中間情況**：清單拿到了，但**一檔都沒抓成功**。
→ 仍走**逐列級**：畫出全部列、全部標 `⚠︎ —`。
**不要**因為「反正全部都失敗」就退回整表級 —— 使用者仍需要看到「我的 12 檔在這裡，只是都沒抓到」。

## §4.「資料時點揭露」規格（取代 Off-Market 那一格）

> 客戶裁示：**不判斷市場開沒開**，改成每張卡都標明這筆資料的**歸屬日與性質**（例：`09-13 收盤`）。

### 4.1 為什麼一定要「歸屬日 ＋ 性質」兩段（不能只給一個日期）

| 只給日期 | 讀者會以為 | 實際可能是 |
|---|---|---|
| `09-13` | 「這是 9/13 那天的市況」 | 9/13 收盤價？9/13 當天 10:00 的盤中報價？9/13 抓到的 8 月營收？ |

→ **日期回答「哪一天」，性質回答「那天的什麼」。** 兩段缺一，讀者就得自己猜，而猜錯的代價是拿收盤價當即時價。

### 4.2 格式規格

**通則**：`<歸屬日> <性質>`，性質用**既有詞彙**，不新造。

| 資料種類 | 格式 | 範例 |
|---|---|---|
| 日頻收盤序列（股價／指數／匯率） | `MM-DD 收盤` | `09-13 收盤` |
| 盤中／即時取得的純量 | `MM-DD HH:MM 取得` | `09-14 15:20 取得` |
| 月頻總經（CPI／PMI／M1B／營收） | `YYYY-MM 資料` | `2026-07 資料` |
| 季頻財報 | `YYYY-Qn 財報` | `2026-Q2 財報` |
| 盤後統計（三大法人／融資／PCR） | `MM-DD 盤後` | `09-13 盤後` |
| 凍結快照（前進式驗證） | `YYYY-MM-DD 凍結` | `2026-08-20 凍結` |

**三條書寫規則**

1. **「歸屬日」是資料自己的日期，不是你抓到它的日期。**
   → 技術上取 `shared/staleness.py:85` `latest_date(df, date_col=...)`（該檔 docstring 原文即稱其為
   「**最新資料日期(as-of)**」）。**不要**用 `fetched_at`（那是抓取時間，見 §4.4）。

2. **年份可省的條件**：**同一頁上所有時點都在今年** → 可用 `MM-DD`；
   一旦頁面上出現跨年的資料（季報、歷史快照），**該頁全部改寫完整 `YYYY-MM-DD`**。
   ⚠️ 不可同一頁混用 —— 混用時讀者無法判斷省略的那個是不是今年。

3. **⛔ 禁用「今天」「剛剛」「最新」這類相對詞。**
   Streamlit 頁面會停在瀏覽器分頁裡好幾個小時，「剛剛」在使用者讀到它的時候可能是 6 小時前。

### 4.3 ⭐ 不知道時點時怎麼寫（**這一格最容易造假**）

**鐵律：不得猜、不得填今天、不得留白。**

| 情況 | ✅ 誠實寫法 | ❌ 禁止 |
|---|---|---|
| 上游**沒有提供**任何日期欄位 | **「資料時點：**來源未提供資料日期**」** ＋ ⚠︎ ＋（可展開）「這是 `<來源名>` 的已知限制，不是這次的故障」 | 填今天／填抓取時間／留白 |
| 有日期欄位但**解析失敗** | 「資料時點：**無法解析（原始值：`<原文>`）**」＋ ⚠︎ | 回退成今天 |
| 本輪**根本沒抓**（idle） | 「資料時點：**尚未載入，本頁沒有任何本輪資料**」 | 顯示上一輪的時點而不說明 |
| 本輪**抓取失敗**，畫面有殘值 | 「資料時點：**本輪取得失敗，畫面上的值可能是上一輪殘留**」＋ 🔴 | 顯示上一輪的時點當成本輪 |
| 這張卡**混合多個時點** | 「最舊 `<日>` ～ 最新 `<日>`（逐塊不同，展開看）」 | 只顯示最新的那一個 |

**已落地的誠實寫法先例**（本組實測，**直接沿用它的語氣**）：
`src/ui/views/page_today.py:610` `AS_OF_NOT_IN_CONTRACT`：

> ⏱ **本頁不顯示「資料時間」**：readiness 側車與 L3 總經契約都沒有逐指標的 `as_of` / `timestamp`
> 欄位（**實測，非推測**）。要顯示真實時間得先擴充 L3 契約 ——
> 在那之前，**寧可什麼都不寫，也不編一個時間出來（§1）**。側車真的有的是「命中來源」，已逐格顯示。

🧠 **【判斷】** 本組建議把上述做法**升級一級**：
**由「什麼都不寫」改為「明說沒有」** —— 即上表第一列的寫法。
理由：「什麼都不寫」在一份**規定每張卡都要有時點列**的規格下，會被讀成「這張卡忘了加」；
明說「來源未提供」則把**限制本身**變成一個可稽核的事實。
⚠️ 這是本組的建議，**不是客戶原話**；客戶若認為維持「不寫」即可，改這一格不影響其他規格。

##### 🔴 2026-09-14 v2 警告：**`gate_for_realtime()` 不得用作使用者可見的警示**

> v1 把 `staleness_days()` ＋ `gate_for_realtime()` 列為「配套」並稱後者是
> 「§1 fail-safe 的既有落點」。**那句話造成一個規則對撞，v1 沒有揭露**（紅隊壓測 (c)；本組重驗成立）。

**對撞長這樣**：
- **§4.5 檢查清單明文禁止**：「沒有任何地方出現『盤中 / 已收盤 / 休市中』這類**需要交易日曆才能判**的字眼」；
- **而 `gate_for_realtime` 要算對，就必須知道「今天收盤了沒有」。**

**實測它會怎麼錯**（情境：週一 09:00 打開，資料停在上週五）：
1. `expected_latest_trading_day(today=週一)`（`staleness.py:26–52`）——
   `holidays` 沒有 caller 注入（§4.4(d) 已證），週一 `weekday()==0 < 5` → **回「今天（週一）」**。
2. `staleness_days(資料=上週五)` → **3**。
3. `gate_for_realtime(3, max_days=1)` → `(False, "⚠️ 此數據為 3 天前的資料，僅供歷史參考…")`

**兩個獨立的錯**：
- **(i) 沒有時刻概念**：`expected_latest_trading_day` 收的是 `date`。台股盤後約 14:30
  （`CLAUDE.md §2.3`），**週一的收盤資料在 09:00 物理上還不存在**，函式卻已把週一當「預期最新交易日」。
  ⇒ **每一個交易日的 09:00–14:30，任何日頻序列都會被多算至少 1 天落後。**
- **(ii) 國定假日**：假日落在週五時，實際最後交易日是週四，資料完全當期卻被算成落後。

⇒ **後果正是本文件 §1.A-4／R-1 在防的東西：每天上午所有卡都掛「僅供歷史參考」，
假警示滿版，稀釋掉真警示。** 使用者三天後就不看它了。

**✅ 現行規定（收窄 v1 的推薦）**：
> **「資料時點」只寫歸屬日 ＋ 性質（§4.2），不做「新不新鮮」的判斷。**
> **⛔ 不得**把 `gate_for_realtime()` / `staleness_days()` 推出的「落後幾個交易日」
> 當成**使用者可見**的警示 —— **本 repo 算不出正確的交易日。**
> 真的需要表達新鮮度時，只寫**客觀可算**的「距今 N 個**日曆**天」，
> 並讓使用者自己判斷（日曆天不需要交易日曆，不會說謊）。

⚠️ **`gate_for_realtime` 本身不是壞函式** —— 它在**內部決策**（要不要把這條資料餵進燈號）

**本條禁的是把它的字串直接印給使用者看。**
🧠 **【判斷】** 這是本組的收窄，不是客戶原話；理由是上面兩個實測的錯。

**其餘配套照常可用**：`shared/staleness.py:54` `staleness_days()`（**內部用**）、

## §5. 反例清單 —— 「看起來合理、其實是造假」的呈現寫法

> 客戶要求 ≥8 個。本節列 **14 個**，其中 **8 個在本 repo 有實測到的真實發生紀錄**（標 📌 實證）。
> 每個附「為什麼違反憲法 §1」。

### R-1｜把「還沒載入」畫成紅色錯誤 📌 實證

**寫法**：冷啟動時 session 沒有值 → 判 `error` → 整頁紅字。
**為什麼是造假**：捏造了一個**不存在的故障**。§1.A 第 4 條原文：
「把『還沒載入』畫成紅色錯誤，等於**捏造一個不存在的故障**；而滿版假紅字會讓**真正的錯誤沒人看得見**。」
—— §1 的失效模式從「假數字」變成「**假警報**」。
**結構防線**：`classify_ui_state` 把 `not requested → idle` 排在 `error → failed` **之前**
（`shared/ui_state.py:201–206`），docstring :178–181 明文：
「Streamlit 每次 rerun 都重跑整頁，session 裡很可能還躺著**上一輪的錯誤字串**。若先判 error，
一個『使用者剛把頁面重置、還沒重新載入』的區塊會**亮紅燈**。」
⛔ **這個判定順序勿對調。**

### R-2｜把「未接線」畫成「無資料」 📌 實證

**寫法**：`wired=False` 的燈用「無資料」文案。
**為什麼是造假**：`shared/ui_state.py:35–36` 原文：
「畫面仍印『無資料』—— 而『無資料』本身就是假話：**不是沒有資料，是沒有人去要**。」
使用者會去按重抓、會去回報「抓不到」，而那盞燈**永遠不會亮**（`page_today.py:1011–1013`）。
**正確**：⛔ 未接線／灰 ＋ `unwired_reason` ＋ `where` 明說沒有出口（§1.5）。

### R-3｜缺值用 `0.00` 顯示

**為什麼是造假**：`0.00` 是一個**有效觀測**的外觀。使用者會拿它做加總、做排序、做決策。
§1 首句：「**錯誤的數字比沒有數字更危險**」。這是最直接的違反。
**正確**：`—` ＋ ⚠︎ ＋ reason（§2.2）。

### R-4｜把「來源沒給」和「值為負／≤0」畫成同一個 `—` 📌 實證（已登記）

**為什麼是造假**：兩者**一個可信、一個不可信**，卻長得一樣。
「本益比 ≤0」＝ 公司在虧錢（**真實、且重要**）；「來源沒給」＝ 不知道。
把可信的觀測藏進「不知道」裡，等於**刪掉一個真實的壞消息**。
📌 本 repo 現況：兄弟交付物 S1-3 §6.5 已登記此問題（⚠️ 本組**未複驗**，僅轉錄）。

### R-5｜時點不明時填今天 📌 實證（repo 內有同形狀的既存寫法）

**為什麼是造假**：憑空宣稱「這是今天的資料」。使用者據以判斷「這很新，可以用」。
📌 **本 repo 的同形狀實例**：`src/compute/macro/macro_helpers.py:606` `rp_scalar()` 把
`last_updated` 設成呼叫端傳入的 `proxy_date`（該檔 :609 docstring 自陳「**呼叫端傳入今天**或總經更新時間」）。
這個欄位**目前沒有直接顯示成使用者可見的「資料時點」**（本組只查證欄位語意，
⚠️ **未窮舉它的所有下游消費點**），但 `shared/data_categories.py:113–127` 已就地登記
「同一欄兩種語意 ⇒ 沒有任何一組門檻對兩者都正確」。
⛔ **新 UI 一律不得顯示這個欄位當時點**（§4.4(c)）。

### R-6｜用 `bool(data)` / `not df.empty` 反推 `requested` 📌 實證（跨 repo 各長過一次）

**為什麼是造假**：`if not data:` **分不出**「還沒叫」與「叫了但失敗」。
`shared/ui_state.py:45–50` 原文：
「那正是 S-4.1 / S-4.3 / S-4.6 三處的共同根因，也是 Fund 端 `helpers/io/freshness.py`
在**另一個 repo 獨立長出同一個 bug** 的原因。**若允許推導，這個模型第一天就退化成原樣。**」
**三層守衛**（:52–60）：① `requested` 必填 keyword-only 無預設值；
② 矛盾即 `raise ValueError`；③ CI 的 AST 守衛比對 `requested=` 與 `has_value=` 綁的運算式不得相同。
⚠️ **但守衛擋不住等價變形**：`page_today.py:63–65` 自陳
「那條守衛只比對 `requested=` 與 `has_value=` 的 AST 是否**逐字相同**……**守衛綠燈不是合規證明**」。

### R-7｜圖表把 NaN 破洞連起來（`connectgaps=True`）

**為什麼是造假**：`station_charts.py:44` 原文：
「把破洞連起來等於**用視覺捏造一段不存在的資料**。」
讀者會在那段假線上讀出趨勢、讀出穿越、讀出轉折 —— 全部不存在。
**正確**：保持斷線（全 repo 現行一律不設 `connectgaps`，`chart_plotter.py:256` 明文 `False`）。

### R-8｜用時鐘 09:00–13:30 粗判「盤中／已收盤」

**為什麼是造假**：假日、颱風假、補行交易日、休市日**全部會被說成「盤中」**。
這是一個「看起來有效、實際是猜的**狀態標籤**」—— 憲法 §1 的定義內。
📌 **本 repo 沒有能力做對這件事**（§4.4(d) 三項實測 ＋ `expected_latest_trading_day` 只扣週末）。
**正確**：客戶裁示的方案甲 —— **不判斷市場開沒開，改標資料時點**。

### R-9｜把「未評估」畫成綠色／正常 📌 實證

**為什麼是造假**：**未評估 ≠ 沒事**。
`src/ui/views/_ui_kit.py:259–261` 原文：
「灰態（`idle` / `empty` / `unwired`）與紅態（`failed`）**一律留白**：那是『沒評估』，不是『評估過沒事』（**未評估 ≠ 綠**）。」
📌 同形狀實證（`page_today.py:88–93`）：修前一條路徑讓 16 盞燈**根本沒被算過**，
畫面卻印出結論「16 盞燈本輪一盞都沒有落在綠 / 黃 / 紅」——
原文判定：「等於畫面上出現一個**這一輪沒發生過的計算**的結論（§1 造假）。」

### R-10｜缺漏的日期寫成 `N/A` 📌 實證（repo 內既存寫法）

**為什麼是造假**：`N/A` 的意思是「**本來就不該有**」。
一筆資料**應該有**日期卻沒抓到，寫 `N/A` ⇒ 使用者以為是設計如此，**永遠不會去修**。
📌 **本 repo 的實例**：`macro_helpers.py:603,614` 在 `missing=True` 時把
`last_updated` 設成字串 `'N/A'`；`:560` `rp_ts()` 也在「任何例外或無法解析」時回 `'N/A'`。
⚠️ 這是**內部資料結構**的取值，不必然直接顯示給使用者（本組**未窮舉**其下游顯示點）。
⛔ **新 UI 一律改用 `—` ＋ ⚠︎**（§2.2 Q2 分支）。

### R-11｜同一個概念在不同元件用不同的缺值符號 📌 實證

**為什麼是造假**：不是單一謊言，是**讓規則失效** ——
使用者在 A 卡學到「`—` ＝ 缺漏」，到 B 卡看到「無資料」四個字，
就會開始猜「這兩個是不是不一樣？」規則一旦不可靠，**整套語彙就沒有資訊量**。
📌 **本 repo 的實例（2026-09-14 v2 更正：不是兩支，至少 10 支）**：
`macro_buckets.py:689` 回 `"—"`、`macro_v2_cards.py:261` 回 `"無資料"`、
`etf_tab_single.py:931–932` 回 `'N/A'`（**這支同時犯了 E-3**）、
`unified_verdict_render.py:42` **完全沒有 `None` 分支**（會印出字面 `None`）——
完整清單與掃描方法見 §2.3 B。
**正確**：見 §2.3 B 的兩段規定（總經卡用 `macro_buckets.fmt_value`；
其餘元件在 L0 新函式落地前，**一律顯式寫 `None → "—"`**）。

### R-12｜把上游錯誤訊息裡的 🔴 直接塞進卡片文案 📌 實證

**兩種壞法，都發生過**：
- **(a) 兩個矛盾的說法**：卡頭 chip 印「⛔ 未接線」，body 文案自己又帶一個「⬜ … 尚未接線」——
  `tab_today.py:203–215` 記載這正是稽核實測到的畫面。
- **(b) 整頁炸掉**：全 repo 帶 `🔴` 的字串有數百處，一個「FRED 連線失敗 🔴」塞進 `Note.why`
  會在 `__post_init__` 變成 `ValueError`，**把一張該畫出來的紅卡變成整頁未捕捉例外**
  （`tab_today.py:150–155`）。原文：「**§1 要的是『紅態看得見』，不是『換一種炸法』。**」
**正確**：先過 `scrub_state_glyphs()` / `upstream_error_why()`，
且 `scrub` **回傳拿掉幾個、呼叫端就地說明**（不靜默修改原文）。

### R-13｜缺值原因套錯 `MISS_*`，給出錯誤指引 📌 實證（憲法點名的事故）

**為什麼是造假**：符號對、**指引錯**，而使用者是照指引行動的。
📌 `CLAUDE.md §-2` 記載的實證：兩個 `MISS_*` 常數選錯，導致**新上市標的**收到
「可以重跑一次」這種**錯誤指引** —— 真正原因是歷史長度不足，**重跑一百次也一樣**。
**結構防線**：`most_fundamental_miss()`（`station_specs.py:537`）＋ `MISS_PRIORITY`（:527）
把「誰勝出」寫死在 L0，**禁止各判燈函式自己挑**（:513–515 原文：
「等於同一個問題有 N 份答案，而且彼此不知道對方存在」）。
**另一條**：側車沒交代原因時**不套任何現成 `MISS_*`**（`page_today.py:403` `UNKNOWN_REASON_WHY`）。

### R-14｜把量綱漂移（`out_of_range`）畫成一般灰態「無資料」 📌 實證

**為什麼是造假**：這是**最毒的一種**（`shared/macro_buckets.py:247` 原文）——
「有資料」且「數字看起來正常」（`^TNX` 回 46.3 而非 4.63、DXY fallback 到 UUP ~27 vs ~105），
**只有範圍守衛擋得住**。畫成灰態「無資料」⇒ 沒有人去修。
📌 同族實證（`macro_buckets.py:256–262`）：`us10y` 自 v18.286 註冊、到 v19.175 才接線，
**中間 4 個版本永久灰燈**，而上游 `fetch_us10y_block` 全程抓取成功 ——
「**沒有任何生產端能回報這種病**」。
**正確**：`MISSING_OUT_OF_RANGE` / `MISSING_NO_EXTRACTION` **必須翻成 `MISS_CONTRACT_DRIFT` 並升紅**
（`page_today.py:388` `READINESS_REASON_TO_MISS`）。
