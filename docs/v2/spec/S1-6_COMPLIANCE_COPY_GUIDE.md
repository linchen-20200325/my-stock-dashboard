# §1 一頁判準（要能背下來）

## 1.0 為什麼不能用禁用詞清單當工具

禁用詞清單**同時**會犯兩種錯，而且兩種都已在本 repo 實測到：

**偽陰性（放過真正的建議）** —— 這句**一個禁用詞都沒有**，卻比「建議買進」更強：

```
src/ui/etf/etf_tab_single.py:437   '分批佈局,停損設 -15%'
```
它指定了**進場方式**（分批）與**部位管理規則**（停損 -15%）—— 已經進到執行細節。
同檔 `:519` 的 `'折價 {x}%，低於 NAV 買入，立即為你創造安全邊際'` 同樣零禁用詞，
卻用了「**立即為你**」這種第二人稱效益承諾。〔甲組實測：這兩句**通過**了現行禁用詞清單〕

**偽陽性（改到無關的字）** —— 「推薦」在本 repo 命中最多的地方是軟體設定：

```
src/ui/pages/api_diagnostic.py:144   '✅ 沒有設定 proxy，所有外連走直連（這是 Streamlit Cloud 推薦設定）'
src/data/portfolio/gsheet_portfolio.py:21   - OAuth（推薦）：使用者在 sidebar 用 Google 登入，自帶 Sheet
```
還有 `CLAUDE.md` / `PROCESS.md` 內數十次的「**總管推薦方案（Recommendation）**」——
**任何全域取代都會破壞憲法本身。**

> **根本原因**：母法禁的是**言語行為（speech act）**，不是**詞彙**。
> 「建議買進」違規不是因為那四個字，是因為它執行了一個**指令式言語行為**。
> 同一個行為可以用完全中性的詞完成（「分批佈局」），
> 也可以用禁用詞完成卻**不是**那個行為（「不要聽信必漲的說法」）。
> **詞表抓不到行為，只有判準抓得到。**

## 1.1 三步驟判準（照順序跑，不可跳步）

### **STEP 1｜這句話是不是「系統對使用者說的話」？**

**不是** → 停，本指南不管它，而且**多半不准改**（見 §4）。四類：

| 類型 | 怎麼認 | 例 |
|---|---|---|
| 註解 / docstring | `#` 開頭、三引號內且非 return 值 | `section_when_buy_sell.py:150` `# 目標價(一比一對稱法)` |
| 資料契約 | 出現在 `.get(...)`／`[...]`／`columns=`／dict literal 的**鍵位置** | `page_hold.py:1882` `_d.get('建議動作', '')` 的 **key** |
| 控制流值 | 被 `==` / `in` / `.startswith` 判讀 | `tab_helpers.py:100` `if '便宜' in val:` |
| LLM 反向護欄 | 在 prompt template 內、語法是**否定式** | `ai_judgment.py:84`「【絕對禁止】喊…必漲…」 |

**是** → 進 STEP 2。
⚠️ **同一行可能同時是兩種**（`page_hold.py:1882` 的 key 不可改、取出來的值該審）→ **人工判讀，禁止批次處理**。

### **STEP 2｜缺項填補測試（主判準）**

把句子切成 **觀測** 與 **行動** 兩半，然後問：

> **要從「觀測」走到「行動」，需不需要代入只有讀者才有的變數？**
> 需要，而系統**把那個變數當成已知值填掉了** → **這就是建議 → 違規。**

只有讀者才有的六個變數（系統一個都沒有）：

| 讀者才有的變數 | 系統有嗎 |
|---|---|
| 可投入資金與流動性需求 | ❌ |
| 持有期間（三個月 vs 二十年） | ❌ |
| 風險承受度與既有部位 | ❌（`data_cache` 有持股，但不含風險偏好） |
| 稅負與交易成本狀況 | ❌ |
| 其他資產／負債（房貸、保單） | ❌ |
| 對這個判斷的信心程度 | ❌ |

**跑一次給你看**：
- 「殖利率 7%」→ 純觀測，沒有行動半 → **合格**。
- 「殖利率 7%，**值得分批佈局**」→「值得」填了風險承受度、「分批」填了資金節奏與持有期間 → **違規**。
- 「殖利率 5.2%，**低於你設定的 7% 便宜區門檻**」→ 行動半不存在，比較基準是**讀者自己給的** → **合格**。

**這條測試不看有沒有禁用詞**，所以 §1.0 那兩個偽陰性它都抓得到。

### **STEP 3｜改寫成「陳述門檻關係」，然後跑三道自我檢查**

改寫的唯一正確方向：**把「結論」換成「觸發了哪條規則」**。

三道自我檢查，**任一不過就是沒改乾淨**：

| # | 自我檢查 | 不過的例子 |
|---|---|---|
| **(a) 動詞檢查** | 改寫後還有沒有指定「讀者該做什麼」？ | 「強烈買進」→「可考慮買進」❌ 還是在講買 |
| **(b) 同義詞檢查** | 我是不是只換了同義詞或加了軟化詞？ | 「強烈買進」→「強烈看好」❌ 言語行為不變 |
| **(c) 遮蔽檢查** | 遮住標籤旁邊所有文字，只留標籤，讀者還能說出它的判定門檻嗎？ | 「甜甜價」❌ 說不出／「殖利率 ≥ 7%」✅ 門檻就在字面上 |

⚠️ **「可 / 值得 / 宜 / 留意」不是免責詞。**
「**值得**分批佈局」與「分批佈局」的差別只有語氣強度，**言語行為完全相同** ——
加一個「可」字不會把指令變成描述，**只會讓它更難被詞表抓到**。

**為什麼線畫在 L2-a 與 L2-b 之間**〔丙組單組推導，未複驗〕：
- **不能更嚴（畫在 L1/L2 之間）**：那會禁掉所有燈號，但 `CLAUDE.md §1.A` 第 4 點
  **要求**用灰／紅區分「未載入」與「真出錯」—— 憲法自己在用顏色編碼狀態。
- **不能更寬（畫在 L3/L4 之間）**：那等於只禁祈使句，
  `etf_tab_single.py:437`「分批佈局,停損設 -15%」會合法通過 —— **放過的正是最危險的一類**。
- **畫在這裡的好處**：判準不依賴語氣強度（語氣是連續的、會吵架），
  而依賴一個**二元且可機械檢查**的性質 —— **判定門檻在不在同一個渲染單位裡**。
  這使它**寫得成測試**（見 §5）。

# §2 可以寫 vs 不可以寫（本指南主體）

## 2.0 改寫的鐵則（每改一句都要回頭看這三行）

> ❌ **換同義詞** —— 「強烈買進」→「強烈看好」＝**沒解決**，言語行為不變。
> ❌ **加軟化詞** —— 「買進」→「可考慮買進」＝**沒解決**，只是更難被詞表抓到。
> ✅ **陳述門檻關係** —— 把「結論」換成「**觸發了哪條規則**」＋「**門檻是多少**」。

**判準**：改寫後的句子，**還有沒有指定「讀者該做什麼」？** 有 → 沒改乾淨。

⚠️ **改寫幾乎一律會讓資訊量「變多」而不是變少** —— 因為原句把門檻藏起來只給結論，
改寫後門檻印在臉上。**如果你的改寫讓句子變得更模糊，那是改錯方向了。**

## 2.3 再平衡偏離（母法唯一有正面規定的一項）

> 母法原文：再平衡一律「**偏離提示、客觀對照、情境試算**」，**嚴禁一鍵再平衡按鈕、嚴禁預設最佳配置推薦**。

### ✅ 先看正確範本 —— repo 內已經有了，直接對齊即可

```
src/compute/etf/portfolio_gates.py:345-346
    f'🔴 需再平衡：{len(_breaches)} 檔偏離超過 ±{_tol:.0f}pp（最大偏離 {_max_dev:.1f}pp）'
src/compute/etf/portfolio_gates.py:351-352
    f'✅ 無需再平衡：所有標的偏離度均在 ±{_tol:.0f}pp 內（最大偏離 {_max_dev:.1f}pp）'
src/compute/etf/portfolio_gates.py:353
    f'已比對 {len(_rows)} 檔的實際權重 vs 你設定的目標權重（總和 {_sum:.1f}%）。'
```
**這三句是母法「偏離提示、客觀對照」的教科書實作**：門檻 `±{_tol}pp` 印在句子裡、
基準是「**你設定的**目標權重」、而且明說比對了幾檔。**新寫的再平衡文案一律比照這個句型。**

⚠️ **它成立的前提**：`portfolio_gates.py` 的 docstring `:270-271` 自陳
「**§1 的核心：沒有目標就沒有偏離**」—— 原碼曾在使用者沒填目標時拿現況當目標，
偏離恆為 0，永遠印「✅ 無需再平衡」。**一個永遠說「你很好」的系統，是在用沉默做背書。**
**L1 客觀對照的成立前提，是基準真的來自使用者。**

# §3 AI 生成內容的規矩（本 repo 最大破口）

## 3.0 為什麼這是最大破口

靜態稽核能指出 **16 個 AI 出口** 與 **5 段會誘導方向性判斷的 prompt**，
但**無法窮舉模型會說什麼**。而本 repo 的結構讓風險最大化：

1. **人設本身在要求 AI 給動作建議**（`persona.py:11, 23`）—— 零禁用詞，卻是根因；
2. **人設走 `systemInstruction`**（`app_ai_service.py:120`、`ai_fetcher.py:47-48`），
   在多數 API 的權重高於 user prompt —— 也就是說，
   **要求給動作的那句話，比禁止推薦的那句話站得更前面**；
3. **16 個出口裡只有 1 處有完整免責**；
4. **沒有任何後置過濾** —— prompt 層只是「**拜託模型自己加免責**」（見 3.4）。

> ⚠️ **一個必須看見的自相矛盾**（本組實測）：
> `financial_health_engine.py` 在**同一次呼叫**裡送出兩句互相牴觸的指示 ——
> `:284` `persona=_PERSONA`（人設：「**請給出明確的動作**」）
> 與 `:210`「**2. 禁止在輸出中推薦任何買賣操作或 ETF 標的。**」。
> **我們同時叫模型給動作、又叫它不要推薦買賣。** 這不是模型的問題，是我們的 prompt 的問題。

## 3.2 免責聲明的三條界線（能做什麼、不能做什麼）

**免責能做的**：確立提供者意圖、提示讀者自行判斷、在**邊緣**情形提供輔助說明。

**免責不能做的（寫進團隊共識）**：

1. ⛔ **不能改變內容的性質。**
   一句「建議股票部位降至 20%，轉入 00679B」**不會**因為頁尾有免責就變成非建議。
2. ⛔ **不能跨越畫面距離 —— 免責必須與被免責的內容同屏。**
   現況實例：`tab_stock.py:622` 已有 caption「…4 桶『非投資建議』…」，
   但它**與同頁 `:633-668` 那排「停利目標 / 建議停損 / 進場價」KPI 不在同一個視覺區塊**〔乙組 F-19〕。
   讀者在 A 處看到指令、在 B 處看到免責，**免責等於不存在**。
   > **可操作的定義**：「同屏」＝ **同一個 `st.container` / `st.expander` / 卡片內，且不需要捲動就能同時看到**。
   > 不是「同一頁」，更不是「同一個 app」。
3. ⛔ **不能解決自相矛盾。**
   系統一邊說「不構成買賣建議」，一邊印 `'🟢 強烈買進'`（`shared/thresholds.py:59`）——
   **矛盾的免責比沒有免責更難解釋**：它證明作者知道界線在哪，卻仍然越線。
   > 對照 `CLAUDE.md §-2`「沒查證的宣稱比沒有宣稱更危險」：
   > **一句自我矛盾的免責，比沒有免責更危險。**

卻會讓測試與被測對象**失去對應關係**。

⚠️ **但反過來要注意**：§2 的改寫**會**讓某些測試轉紅（丁組列出至少 17 條 (a) 類必須同批改的）。
那時該做的是**同步更新測試**，**不是**先改測試讓它變綠。
**判準**：改測試的理由必須是「**production 的正確字面變了**」，
不能是「**這樣測試就會過**」。兩者差別見 §5.3。

## 5.2 檢出規則：登記制，不要啟發式

沿用 `test_views_no_unverified_universal_claims.py` 的 REGISTRY 設計，理由三條：
1. **啟發式擋不住換句話說的人**（`強烈買進` → `強力買進` → `積極買進` → …）；
2. **啟發式方向也錯** —— 「附近有『非投資建議』四個字就放行」是一個**可以被隨手滿足**的條件；
3. **登記制強迫逐句判讀一次**，並把判讀留成白紙黑字給下一個人複查。

**每一條命中登記成一筆**：`origin`（來源識別，例 `classify_yield_zone(7.0)[0]`）、
`snippet`（正規化後的字面特徵，**≥10 字、不寫行號** —— `CLAUDE.md §8.2.A.0` 規則 1）、`kind`、`why`。
`kind` 只有兩種：`ALLOWED`（已判讀為不構成合規問題，例 `⚪ 未評估`）／`PENDING`（**紅燈**）。
**不留 `# noqa` 之類的行尾逃生口** —— 「**留但書等於留引用點**」。

**`_normalize` 必做**：去空白、去 `*`、去反引號、去各式引號括號、**去 emoji**、去 HTML tag。
理由〔丁組實測〕：`etf_tab_grp_compare.py:249` 寫的是 `殖利率≥7%🟢強烈買進`（無空白、夾 emoji），
`etf_tab_single.py:435` 寫的是 `🟢 <b>強烈買進（特價）</b>`（夾 HTML tag）——
**使用者眼睛看到的一模一樣，字面 grep 卻掃不到。**

### ⭐ 可達性證明怎麼做（三層，缺一層就是假護欄）

**核心原則：把「這個字串真的會被印出來」寫成一條會失敗的斷言，而不是靠相信。**
**斷言的方向必須是「我預期它出現」，不是「我預期它不出現」** ——
因為「不出現」在死碼上永遠成立，「出現」在死碼上會當場紅燈。

#### **R1｜分支可達性（對函式輸出）**

對每一個要守的分支，餵**真的會走到那個分支**的輸入，然後**斷言輸出確實是該分支的字串**。

```
設計（虛擬碼，非實作）：
  r = calc_dividend_yield_357(price=100, avg_div=8, div_years=5)
  assert r['zone_code'] == 'cheap'          ← 先證明我真的走到了 cheap 分支
  assert '7%' in r['msg']                   ← 再驗它產出的是新措辭
  assert not _scan('calc_dividend_yield_357.msg', r['msg'])   ← 最後才驗合規
```
**三行的順序不可顛倒**：
- 少了第 1 行 → 分支若死了，第 2、3 行會在一個**空字串或別的分支**上通過；
- 第 3 行單獨存在 → **就是假護欄**（見上表第 4 例）。

> **這一層會讓「那段是死碼」當場現形**：分支若不可達，第 1 行 `zone_code == 'cheap'` 就紅。

#### **R2｜呼叫點參數可達性（對「被 caller 餵死」的分支）**

R1 只證明**函式自己**走得到。第 4 例的坑在**呼叫點**：函式分支寫得好好的，
但唯一的 caller 硬寫 `''` 進去。**這一層專門擋這個。**

```
設計：對每個「以字串內容分支」的函式，斷言其 production caller 實際傳入的值域非退化。
  以 generate_ai_comment 為例：
    · AST 掃 section_op_recommendation.py 組 payload 的那個 dict literal
    · assert payload 的 'val_label' / 'trend' 兩鍵的值 **不是** 字面空字串
    · 若是 → 紅燈，訊息寫：「此鍵恆為空 ⇒ app_ai_service 的 5 個估值/趨勢分支
      在 production 不可達；此處的合規守衛是假護欄，請先修接線或刪除該分支」
```
> ⚠️ **這一條會在今天就紅。** 那是**正確的** —— 它紅的意思是
> 「你有一段掛著合規風險字串、卻永遠跑不到的死碼」。
> **處置是修接線或刪死碼，不是把這條測試拿掉。**
> （`CLAUDE.md §-1.5.F 判定 3(4)`：因本次改動才變成沒用的東西要在本次清掉；
> 但這一段是**本次改動之前就已經**是死碼 → 依 §-1 **登記，不動**，
> 守衛標成 `KNOWN_UNREACHABLE` 並附證據，**不得**用 `ALLOWED` 混過去。）

#### **R3｜渲染面可達性（對只在 UI 出現的字面）**

斷言字串出現在 **`st.*` 的實參位置（AST）**，而不是「出現在這個 `.py` 檔裡」。
後者會把註解、docstring、被 `if False` 包住的死碼一起算成「有印」。

```
設計：
  · 走訪 ast.Call，篩 func 為 st.markdown/caption/info/warning/success/error/metric/expander
  · 只取實參中的 Constant(str) 與 JoinedStr 的字面片段
  · 命中的 snippet 才進 REGISTRY
```

### 三件套（沿用既有 house style，缺一條就是假護欄）

| # | 測試 | 範本 | 內容 |
|---|---|---|---|
| **D1** | **守衛的守衛**（正樣本必須被抓到） | `test_user_facing_copy_guard.py:145` | 用**真的踩過的字串**當樣本：`'🟢 強烈買進'`、`'建議逢高減碼'`、`'策略1 存股首選'`、`'可分批布局，勿一次梭哈'`、`'積極買進區'`、`'可大膽買進，股息都進口袋'`、`'分批佈局,停損設 -15%'`、`'大買 50%'`、`'該加碼'`。<br>⚠️ **樣本寫死在測試檔內，不從 production 讀** —— 否則 production 改了樣本跟著變，守衛就永遠抓不到東西 |
| **D2** | **反向守衛**（合法文案不得被誤判） | `test_user_facing_copy_guard.py:159` | 樣本要含**長得很像違規、其實是誠實揭露**的句子：`'⚪ 未評估'`、`'無股價，357 殖利率法則不適用（不以 0% 代替，避免誤判為超貴）'`、`'這一輪沒有建議換股'`、`'本站不硬湊一檔給你換'`、`'🔴 過熱｜乖離+30%（>25%）、RSI 78（>70）'`、`'✅ 無需再平衡：所有標的偏離度均在 ±5pp 內'`。<br>**沒有這一條，守衛會逼人把有價值的警語整段刪掉**（§4.5） |
| **D3** | **掃描面非空** | `test_user_facing_copy_guard.py:165` | 斷言掃到的字串段數有**下界**（函式輸出 ≥ 9 段、資料結構 ≥ N 段、AST 實參 ≥ N 段）；**掃不到檔案／目錄不存在／`ast.parse` 失敗一律 `AssertionError`，不 skip、不靜默過**。<br>理由：**欄位改名讓守衛靜默失效，是最糟的失敗模式** |
| **D4** | **突變測試**（v3 §03-1「拔掉修復邏輯必須轉為紅燈」） | `test_b2b_pcr_scale.py:334, 342` | 把**舊的（違規的）字面**合成成字串餵給掃描器，斷言它**會被抓到**；再合成一個「只是在註解／docstring 裡提到舊寫法」的樣本，斷言它**不會**被抓到。<br>這等於在測試裡直接做了一次突變，**不必真的去改 production** |

### ⚠️ 還要防一件事：**可達性證明自己也可能是假的**

如果 R1 的第 1 行寫成 `assert r['zone_code'] in ('cheap','fair','dear','overpriced','na')`，
那它**永遠成立** —— 又是一個假護欄。
> **規則**：可達性斷言**必須釘死單一預期分支**（`== 'cheap'`），不得用集合、不得用 `in`、不得用 `or`。
> **一個分支一條測試。** 這樣才能在該分支死掉時精確地紅。

## 5.4 這支守衛**不該**做的事

1. ⛔ **不要用「全 repo 中文字面黑名單」** ——「買進」兩個字在 `etf_tab_portfolio.py:864`
   是 `act['動作'] == '買進'` 的**控制流值**，在 L1 fetcher 是**上游 TWSE 欄名解析**。
   掃到它們只會製造**改不了的紅燈**。射程必須排除 L1 欄名解析與所有控制流值，**並在檔頭寫清楚為什麼**。
2. ⛔ **不要斷言「一定含免責聲明」** —— 那是可以被隨手滿足的條件：
   下一個人只要在違規句旁貼一句「非投資建議」就綠了（而 §3.2 第 3 點說明那反而更糟）。
3. ⛔ **不要把它接到 `src/compute/**` 的 verdict 常數上** —— 那些是控制流值（§4.2），
   守衛紅了只有兩條路：改行為（超出窗口）或加白名單（守衛自廢）。
4. ⛔ **不要在 `-m "not slow"` 的預設 lane 之外** —— `pytest.ini` 預設排除 slow，
   守衛若被標 slow 會變成「本機從來不跑」。

### 議題 1｜狀態標籤／燈號算不算「建議」（**最承重的一條**）

- **母法原文怎麼說**：「全站不產生任何直接買賣建議」＋六個禁用詞。
- **空白在哪**：母法**沒有規定狀態標籤**（「便宜區」「過熱」「健康」）。
  它既沒說可以，也沒說不可以。
- **我們填了什麼**：丙組提出 **L2-a／L2-b 切法** —— 標籤**在同一個渲染單位內附帶自己的判定式**
  （`🔴 過熱｜乖離+30%（>25%）`）→ 放行；標籤**脫離判定式單獨出現**（`🟢 甜甜價`）→ 以建議處理。
  **這是往「有條件放寬」的方向填，縮小了客戶的 gate。**
  〔丙組自陳：**本組提出的政策新增，非從母法推導的唯一解，單組未複驗**〕
- **兩邊理由並陳**：
  - **支持放行（我們填的方向）**：母法自己允許「客觀對照」，而門檻透明的燈號**就是**客觀對照的視覺化；
    且 `CLAUDE.md §1.A` 第 4 點**要求**用灰／紅區分「未載入」與「真出錯」——
    憲法自己在用顏色編碼狀態。全禁會與憲法直接衝突。
  - **支持不放行（更嚴）**：「便宜／昂貴」在**投資語境**已被指令化 ——
    證據就在本 repo 自己的 SSOT：`shared/thresholds.py:11` 把同一個區間寫成
    「**便宜價 / 強烈買進區**」。**本專案自己把兩者當同義詞並列** ——
    既然作者本人認為可互換，就很難主張「便宜是中性描述」。
- **✅ 推薦方案**：**保留燈號，但門檻必須印在同一個渲染單位內**（即 §2 全部改寫的方向），
