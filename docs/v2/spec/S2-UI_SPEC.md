## 2. 展開佐證觸發器

> **搬自** `S1-3B` Part 2.4（規格沿用 `S1-3:68-84`；顆粒度為 ★-02 新定案）。

### 2.1 觸發器規格（逐條寫死）

| 項目 | 規格 |
|---|---|
| **外觀** | 次級**文字**按鈕，樣式等級低於主 CTA。文字固定「展開佐證 ▸」／展開後「收合佐證 ▾」 |
| **位置** | ⭐ **該區塊標題列的最右側**，與標題同一行、右對齊 |
| **可點範圍** | 只有那串文字 ＋ 箭頭。**標題本身不可點** |
| **行動裝置** | 同一顆，點擊區至少 **44×44 CSS px**（文字周圍補 padding 達標，視覺上仍是文字按鈕） |
| **⛔ 禁止** | **卡片本身可點**、整列 `<tr>` 可點、標題可點、hover 自動展開、卡片右上角小箭頭 |
| **Deep Link 必須長得不一樣** | Deep Link 帶 `↗`（離開本頁）；展開佐證帶 `▸`（就地展開）。⛔ 不得長得一樣 |

> ⚠️ **實作面已知落差**：Streamlit 原生 `st.expander` 的開合控制項在**標題左側**，與本規格「標題右側」**方向相反**。
> 要做到必須改用「標題列切兩欄 ＋ 右欄放次級按鈕 ＋ 自行控制展開區」的組法。
> → 屬技術實作細節，落地方式見 `S2-ENG_SPEC §7`。

### 2.2 ★-02 顆粒度：兩級制

- **預設**：**一個區塊一顆**，位置在區塊標題右側。
- **例外**：元件個別處於 **⛔ 未接線／🟠 門檻已失準／🔴 錯誤** 時，該元件**就地**額外帶一顆展開，內容只講「這一個」為什麼。

**為什麼是兩級制**（三條，搬自原文）
1. **M-1 核准的就是區塊級**（頁1 葉2、頁4 ③ 的 note 都寫「點左表右側就地展開」）。**逐元件是偏離核准線框。**
2. **逐元件會讓觸發器數量爆炸**：頁1 葉2 光是燈就 16 盞 → 16 顆 44×44 按鈕，直接吃掉 §6 算出的 197px 每欄硬底線。
3. **但例外必須保留**：那三種情況的原因（`unwired_reason` / `degraded_reason` / 例外型別）**逐元件不同，合併展開就看不出是哪一個壞了**。

**不決定的後果**：實作組會在頁1 葉2（16 盞燈）與頁4 ③（12 檔燈牆）各自選一種，兩頁的展開手勢從此不一致。

**⭐ `why` 與 `where` 必須指向同一個世界觀**（`page_today.py:507-511` 記載的 2026-09-09 真實 bug）

> 同一張卡的 `why` 說「這是**程式要修**的訊號」，`where` 卻說「按一次就會**重抓**這一源」——
> **同一張卡上兩句互相打臉，而且照 `where` 做的人會白按。**

## 4. 數值三分 ＋ 決策樹

> **搬自** `S1-3B` Part 2.6（其沿用 `S1-4 §2`；含紅隊 §2.7 新增條）。**母法釘死，不得改。**

`0.00` ＝ 正常有效數值（正常文字色）｜`N/A` ＝ 不適用（灰字，⛔ 無圖示）｜`—` ＝ 缺漏（灰字 ＋ ⚠︎ 警示圖示）。**三者不可混。**

| | 這個數字**存不存在**？ | 它**該不該存在**？ | 使用者該做什麼 |
|---|---|---|---|
| `0.00` | **存在**，而且就是 0 | 該 | **採信它** —— 零是一個觀測值 |
| `N/A` | 不存在 | **本來就不該存在** | **什麼都不用做** |
| `—` | 不存在 | **該存在，但這次沒拿到** | **看旁邊的說明**，決定要不要重抓／回報 |

- **把 `—` 寫成 `0.00`** ⇒ 使用者拿一個不存在的觀測去做決策（憲法 §1 最核心禁令）。
- **把 `—` 寫成 `N/A`** ⇒ 使用者以為設計如此，**永遠不會去修**。
- **把 `N/A` 寫成 `—`** ⇒ 畫面長期掛一排 ⚠︎，真正的缺漏被淹沒（假警報稀釋真警報）。

### 4.1 決策樹（對**每一個要印出來的數字格**依序問）

```
Q1 ─ 這個標的／這張表，「結構上」有沒有這個概念？
      ├─ 沒有 ─▶【N/A】灰字，⛔ 不加任何圖示
      │          ⚠️ 這一格與「這一輪抓不抓得到」無關 —— 抓一百次也一樣
      └─ 有 ─▶ Q2
Q2 ─ 這一輪，上游有沒有給回一個值？
      ├─ 沒給 ─▶【—】灰字 ＋ ⚠︎
      │          ⛔ **必附 reason** —— 沒有 reason 的 `—` 等於「不知道為什麼沒有」，
      │             那是把診斷責任丟給使用者
      └─ 有給 ─▶ Q3
Q3 ─ 這個值通過範圍守衛（valid_min / valid_max）了嗎？
      ├─ 沒過（out_of_range，量綱漂移）─▶【—】＋ ⚠︎，且**狀態升紅** ⑩ 錯誤

      └─ 過 ─▶【照實印】正常文字色；值剛好是 0 → 印 `0.00`，與其他有效值同色同格式
```

## 5. 資料時點揭露（取代 Off-Market）

> **搬自** `S1-3B` Part 2.7（其沿用 `S1-4 §4`；含 ★-05 新定案）。**落實客戶拍板一。**

### 5.1 為什麼一定要「歸屬日 ＋ 性質」兩段

**日期回答「哪一天」，性質回答「那天的什麼」。** 缺一，讀者就得猜，而猜錯的代價是拿收盤價當即時價。

| 資料種類 | 格式 | 範例 |
|---|---|---|
| 日頻收盤序列（股價／指數／匯率） | `MM-DD 收盤` | `09-13 收盤` |
| 盤中／即時取得的純量 | `MM-DD HH:MM 取得` | `09-14 15:20 取得` |
| 月頻總經（CPI／PMI／M1B／營收） | `YYYY-MM 資料` | `2026-07 資料` |
| 季頻財報 | `YYYY-Qn 財報` | `2026-Q2 財報` |
| 盤後統計（三大法人／融資／PCR） | `MM-DD 盤後` | `09-13 盤後` |
| 凍結快照（前進式驗證） | `YYYY-MM-DD 凍結` | `2026-08-20 凍結` |

**三條書寫規則**
1. **「歸屬日」是資料自己的日期，⛔ 不是你抓到它的日期。** ⛔ **不要用 `fetched_at`**。
2. **年份可省的條件**：同一頁全部在今年 → 可用 `MM-DD`；一旦出現跨年資料，**該頁全部改完整 `YYYY-MM-DD`**。⛔ 不可同頁混用。
3. ⛔ **禁用「今天」「剛剛」「最新」這類相對詞。** Streamlit 頁面會停在瀏覽器分頁裡好幾個小時。

### 5.2 ⭐ 不知道時點時怎麼寫（最容易造假的一格）

**鐵律：⛔ 不得猜、⛔ 不得填今天、⛔ 不得留白。**

| 情況 | ✅ 誠實寫法 | ❌ 禁止 |
|---|---|---|
| 上游**沒有提供**任何日期欄位 | 「資料時點：**來源未提供資料日期**」＋ ⚠︎ ＋（可展開）「這是〈來源名〉的**已知限制，不是這次的故障**」 | 填今天／填抓取時間／留白 |
| 有日期欄位但**解析失敗** | 「資料時點：**無法解析**（原始值：`〈原文〉`）」＋ ⚠︎ | 回退成今天 |
| 本輪**根本沒抓**（③ 未載入） | 「資料時點：**尚未載入，本頁沒有任何本輪資料**」 | 顯示上一輪時點而不說明 |
| 本輪**抓取失敗**，畫面有殘值 | 「資料時點：**本輪取得失敗，畫面上的值可能是上一輪殘留**」＋ 🔴 | 顯示上一輪時點當成本輪 |
| 這張卡**混合多個時點** | 「**最舊 `〈日〉` ～ 最新 `〈日〉`**（逐塊不同，展開看）」 | 只顯示最新的那一個 |
| **混合 ＋ 部分不明同時成立**（★-07a） | 「最舊 `09-11` ～ 最新 `09-13`；**其中 2 項來源未提供資料日期**」＋ ⚠︎ | 只寫其中一半 |

### 5.3 🔴 拿不到歸屬日的來源清單（實測）

| 來源／路徑 | 為什麼拿不到 | 時點列該怎麼寫 |
|---|---|---|
| **L3 canonical 總經契約 `get_macro_state()`** | 契約**只有 9 個 key，沒有 `as_of`／`timestamp`**（`page_today.py:71-75`） | 「**來源未提供資料日期** —— L3 契約無此欄位」 |
| **readiness 側車（16 盞燈逐燈紀錄）** | 同上，無逐指標時間欄（`page_today.py:610`） | 同上；**改顯示側車真的有的「命中來源」`hit_source`** |
| **純量型 registry entry** | `macro_helpers.py:606` `rp_scalar()` 把 `last_updated` 設成 ≈ 今天 | 🔴 ⛔ **絕對不要顯示這個欄位當時點** |
| **`data_registry` 的 `last_updated`（整體）** | 語意是混的（`shared/data_categories.py:113-127` 自陳） | ⛔ 不可直接顯示 |
| **`fetch_monitor` 的 `last_called_at`** | `shared/fetch_monitor.py:56` ＝ `datetime.now(_TW_TZ)` ＝ **呼叫時間** | 可顯示為「`MM-DD HH:MM` **取得**」，⚠️ **必須寫「取得」兩字** |

### 5.4 ★-05 定案：時點列 ⛔ 不做新鮮度判斷

> 「資料時點」**只寫歸屬日 ＋ 性質，⛔ 不做「新不新鮮」的判斷。**

**理由（紅隊實測）**：`expected_latest_trading_day()` **收的是 `date`、沒有時刻概念**，且 `holidays=` 零 caller 注入
⇒ 週一 09:00（台股未收盤）它仍把週一當「預期最新交易日」，於是 `gate_for_realtime(max_days=1)` 會在
**每個交易日的整個上午**對正常資料發出「⚠️ 僅供歷史參考」。**滿版假警示稀釋真警示。**

⇒ 需要新鮮度時，用「**資料歸屬日 vs 前一個已知歸屬日**」或明確標為「**距今 N 個日曆天**」；
⛔ **不得**用 `expected_latest_trading_day` 推出的「落後幾個交易日」當使用者可見的警示。

### 12.4 ⭐ ★-03 的可及性代價（🆕 本份新發現，原稿未討論）
