## 為什麼要單獨講這件事

`spec/` 與 `audit/` 長得很像 —— 都是大段 Markdown、都有編號、都有表格、都講得很篤定。
**但它們是兩種完全不同的東西，混用會直接做錯事。**

| | **規格**（`../spec/`、`../wireframe/` 的線框） | **稽核軌跡**（**本目錄**） |
|---|---|---|
| 回答的問題 | 「**應該**長什麼樣？」 | 「當時**實際**查到什麼？」 |
| 本質 | **主張**（提案） | **證據**（紀錄） |
| 生命週期 | 被拍板 → 被實作 → 被驗收 | **寫完就凍結**；它描述的是**某個 commit 當下的現況** |
| 過期方式 | 被新版規格取代 | **會隨 code 改動而失真**，但**不會自己更新** |
| 正確用法 | 照它做 | **引用它**（附量測日與基準 commit） |
| ⛔ 錯誤用法 | — | **照著它做** |

**一句話**：把稽核軌跡當規格照做，等於把「**現況有這個問題**」誤讀成「**我們決定要這樣做**」。
本目錄裡大量出現的行動語（加碼／減碼／買進／停利／持股 %）**全部是引用現行 code 的字串常數**，
是**證物**，不是**指示** —— 對齊客戶明令「不得產生直接買賣建議」。

## ⚠️ 讀本目錄任何一份之前必須知道的三件事

1. **每一份都綁定一個基準 commit 與量測日。** 多份寫的是 `fab88a7` / 2026-09-14。
   **code 一改，這些數字就失真，而檔案不會自己更新。** 引用時**務必連量測日一起引**。
2. **「第二組」指的是它稽核的對象，不是它自己。**
   本目錄有幾份是對**另一份文件**的獨立複驗（見下表 ⭐ 標記）——
   那代表**被它看的那一份**有第二雙眼睛，**不代表這一份自己被驗過**。
   ⛔ 紅隊報告本身仍然是**單組結論**。
3. 🔴 **沒有任何一份跑過實機 Streamlit。** 所有「畫面會顯示 X」都是讀 render 函式推導的，
   **沒有一張截圖**（見 `../README.md` §2 第 3 點）。

　　→ 掉了量測日、掉了基準 commit、掉了「單組」、還把**例示數**寫成**全站數**。

　　→ 那是**風險評估**，不是**核准的施工單**。要動字串屬 UI 文案變更，

　　且依 `§-1`，**沒有指派、沒有 bug 觸發就不要動工**。
