# UI-B 線框草稿：頁2「找標的」選股結果 ＋ 頁5「憑什麼」門檻對照表

日期 2026-09-08　／　產出：文字線框，交客戶拍板　／　**本輪未寫任何 code、未改 repo 任何檔案**

## 〇、先講一句話結論

兩個畫面犯的是**同一個錯**：把「**系統有回應**」講成「**答案算完了**」。

- 頁2：五個因子只有一個算出東西，畫面掛綠燈、標題寫「綜合入選」。
- 頁5：兩條「刻意不算燈」的參考線混進燈的清單，於是 16 盞被印成 18 盞。

兩者都不需要新的顏色、也不需要新的狀態模型 —— **要修的是「畫面說了什麼」，不是「系統怎麼判」**。

## 一、實測到的事實（先分清哪些是事實、哪些是我的判斷）

### 1.1 頁2 選股結果：綠燈是怎麼來的

`build_screen_result_card()` 呼叫共用的狀態判定：

```
classify_ui_state(requested=有沒有按過送出,
                  error=有沒有例外,
                  has_value=有沒有選出至少一列)
```

**綠燈的條件就是「選出了至少一列」。** 有幾個因子真的算進去，這個判定**完全沒有看**。

同一張畫面上，四句話彼此矛盾（全部實測命中）：

| # | 畫面上的字 | 出處 |
|---|---|---|
| 1 | 🟢 **運作中** | 狀態晶片，`has_value=rows>0` |
| 2 | 🔭 存活池 359 檔 → **綜合入選 50 檔** | 卡片標題 |
| 3 | 排序：**綜合評分（各因子百分位平均）** | 表單第 ③ 格的說明 |
| 4 | 本次因子：**僅基本面四項全過** | 結果表上方的 caption |
| 5 | 五個因子都走 L3 service，**已全部接線** | 表單下方常駐揭露 |

第 3 句承諾「各因子平均」，第 4 句自陳「只有基本面」，第 5 句說「全部接線」——
**三句話指向三個不同的世界，而燈是綠的。**

⚠️ 第 4 句還有一個獨立的問題：`summarize_factor_hits()` **只會替缺貨 / RS / 跨季三個因子產生片語**，
EPS 與本益比**永遠不產生片語**。所以使用者只勾 EPS（那正是預設值）時，
`hits` 是空的 → 印「僅基本面四項全過」，**但 EPS 明明有被拿來排序**。
也就是說第 4 句在「只勾 EPS」這個**最常見的情境**下**也是錯的**，只是錯在另一個方向。

### 1.2 頁5 門檻表：16 vs 18 的真正原因

**這是版面問題，不是資料問題。資料是對的，而且是刻意被分開的。**

L0 `shared/macro_buckets.py` 有兩份清單：

- `BUCKET_DANGER_SPECS` = **16 盞**（長期 3 / 中期 6 / 短線 3 / 籌碼 3 / 新聞 1）
- `REFERENCE_TREND_SPECS` = **2 條**（新台幣匯率、加權指數），`bucket="reference"`

L0 的原始註解逐字寫著（不是我的詮釋）：

> 客戶裁示（2026-08-27）：台幣與加權指數要在總經 v2 第 2 層畫走勢，但**不算一盞燈**
> —— 不進「x/16 有值」的分母、不進五桶 worst-of 彙總、不進訊號可信度卡。
> ……把不算燈的東西放進去再靠旗標排除，等於要求每一個現有與未來的消費端都記得過濾；
> **漏掉一個，分母就悄悄變成 18，而畫面上完全看不出來**。

**頁5 就是那個漏掉的消費端。** 它把兩份清單相加、一律標成 `family="總經"`，
然後印出「總經燈 …（18 盞）」。

而且最諷刺的是：這兩列的「在防什麼」欄位**原樣透傳 L0 的說明**，
所以同一個畫面上會出現：

```
標題：  總經燈 —— 五桶紅綠燈（🚦 今天 那一頁在用的）（18 盞）
        ...
其中一列：加權指數 │ reference │ — │ ... │ 日 K 走勢。參考走勢：不判燈、
                                            不畫門檻線、**不計入 16 盞燈的分母**。
```

**畫面自己承認它多算了。** 這一列不必查證就知道是錯的。

### 1.3 頁5 門檻表：另外三個實測問題

| 現象 | 實測根因 |
|---|---|
| 加權指數「門檻」空白、「已知限制」寫**正常** | `taiex` 的 yellow/red 都是 `None`（**刻意的**：它不判燈）。三個旗標 `wired/discriminative/emits_level` 全 True → 旗標欄算出「正常」。**「正常」在這裡是假話**：它不是一盞正常的燈，它根本不是燈。 |
| 融資餘額標「門檻已失準」但 2500/3400 照印 | `margin` 的 `discriminative=False`。**這一盞真的會亮、真的在用這兩個數字**，只是門檻已經失去判別力。 |
| 外資現貨淨買賣標「未接線」但 0 / −200 照印 | `foreign_net` 的 `wired=False`。**這一盞從來不會亮**，那兩個數字是一份**從未生效的規格**。 |
| 「分組」欄印 `long / mid / short / chips / news / reference / health / screen / stock / timing` | 表格直接印 L0 的內部欄位。**中文名稱其實已經存在**：`BUCKET_META` 有 🌳長期／📈中期／⚡短線急殺／🧩籌碼／📰新聞。表格沒去查它。持股的四組（health/screen/stock/timing）與 reference **則完全沒有中文 SSOT**。 |

⚠️ 還有一個**沒被列進任務描述、但我認為更嚴重**的問題：
**「已知限制」欄只印旗標名稱，不印原因。** L0 明明有 `unwired_reason` 與 `degraded_reason`
兩個欄位，但表格的七欄（這一盞／分組／方向／門檻／值從哪來／在防什麼／已知限制）
**一欄都沒有帶它們**。使用者在這張表上看到「門檻已失準」四個字，
**得不到任何一句解釋**，只能看到旁邊那兩個仍然印得好好的數字。

### 1.4 一個會影響實作的硬限制（必須先講）

共用的 `Card` 有這條驗證（`tab_today.py`）：

```
非 live 狀態 + 帶了結論文字 → 直接 raise
（「只有 live 能給結論」）
```

**這條會擋住「部分成功仍然顯示結果」的做法。** 但同一份 repo 的 `render_card()` 說明裡，
2026-09-07 的獨立稽核已經裁定過相反方向的原則：

> `degraded` **不是「沒有東西可給」**，所以「一律留白」不是安全解。
> 載 **觀測** → 照出；載 **判決語** → 留白。

兩處對「橘態能不能給文字」的處理**目前不一致**。我的線框選了稽核裁定那一側
（**觀測照出、判決留白**），理由寫在 §2.4。**這一點需要總管在實作前拍板走哪一邊。**

## 二、頁2「選股結果」線框（三態）

### 設計原則（先講，三張圖才看得懂）

**燈號回答一個問題，而且只回答一個：「這張清單，能不能照著它的字面意思用？」**

- 五個勾選的因子全部有算出分數 → 🟢。清單就是它自稱的那個東西。
- 服務有回應、清單有內容，但**有勾的因子沒算進去** → 🟠。清單能用，但**不是**它原本自稱的東西。
- 服務掛了 / 契約壞了 → 🔴。
- 沒按過送出 → ⬜（灰）。跑完 0 檔 → ▨（灰，這是有效結果）。

**新增的不是狀態，是「排序基準」這個資訊。** 現在畫面上「排序方式」是一句寫死的靜態說明
（表單裡那句「綜合評分（各因子百分位平均）」），它**不隨結果改變**。
線框把它改成**跟著結果走的一行事實**。

**四個關鍵設計決定：**

**(B-1) 燈改成 🟠，不是維持 🟢。**
> 分類：**修正錯誤**。
> 理由：畫面自己承諾「各因子百分位平均」。只有 1 個因子算出東西時，那句承諾沒有兌現，
> 而燈號是使用者判斷「這張清單能不能信」的第一個訊號。
> **機制不需要新造** —— 共用的狀態判定本來就吃一個 `discriminative` 參數，
> 而且隔壁的產業熱力圖卡**已經在用它**（部分抓到 → 橘）。選股卡只是沒傳。
>
> ⚠️ **反方向的意見我也寫出來**：有人會說「綠燈的字是『運作中』，它只承諾服務有回應，
> 沒承諾因子跑完」。那個讀法在字面上成立 —— 但**沒有任何新手會這樣讀**，
> 而且它跟同一張卡上「綜合入選」四個字直接打架。
> 憲法 §1 的判準是「這是在解決問題，還是在掩蓋問題」，不是「這句話字面上有沒有講錯」。

**(B-2) 橘態的文字必須改。**
共用狀態表把橘態的名稱寫死成「**門檻已失準**」。那是門檻領域的詞，
**這張卡沒有門檻**，硬套會讓使用者去找一條不存在的線。
線框用「**部分因子未計入**」。
> 分類：**修正錯誤**（機制）＋ **需要總管拍板**（實作方式）。
> 這需要讓「橘態的顯示字」可以由卡片自己給，而不是全站共用一個字。
> 我**不建議**為此新增第八個狀態或新顏色 —— 憲法明文「不新增任何其他顏色」，
> 而且問題出在**標籤**不在**狀態**。

**(B-3) 清單照樣顯示，不隱藏。**
> 分類：**修正錯誤**（維持現行行為）。
> 理由：那 50 檔是**真的**依 EPS 百分位排出來的，它是一個有效的單因子排名。
> 藏起來等於丟掉真實資訊，那是另一種說謊。
> 憲法 §1 禁的是**假造**與**誤標**，不是「不准給不完整的東西」——
> 只要**標題不再宣稱它是綜合分**，顯示它就是誠實的。

**(B-4) 缺料的欄位留白，不填 0、不填 —— 以外的任何值。**
> 分類：**修正錯誤**。
> 這與板塊熱力圖「缺格留白不填 0」的既有處置一致（那句文案已經在 repo 裡）。
> 表格下方那句「空白代表沒有這個數字，不是 0 分」是**新增的一行說明**，
> 因為表格裡的「—」對新手來說看起來就像「零」或「很差」。

⚠️ **這張圖踩到 §1.4 那條硬限制**：橘態帶了標題文字（「依 1 個因子排序，取前 50 檔」），
而現行的 `Card` 驗證會擋。我選擇讓它通過，理由是稽核已裁定的那條線：
**這句話是「觀測」（我依什麼排的），不是「判決」（這 50 檔很好）**。
若總管決定維持現行限制，退而求其次的版本是**把這句話降到 ⚠️ 區塊的第一行**，
卡片本體只留燈與標題 —— 誠實度不變，但使用者要多讀一行才知道發生什麼事。**我不推薦。**

## 三、頁5「逐盞門檻對照表」線框

### 3.1 先把清單切開（這是本頁最重要的一刀）

現況：一張表，18 列，標題寫「總經燈（18 盞）」。

### 3.4 為什麼是「標記」而不是「隱藏」（任務問題 3 的正面回答）

**我的判斷：一律標記，一律不隱藏 —— 但必須把數字從「可用的門檻」降級成「規格」。**

先把兩者的代價攤開：

| | 隱藏 | 標記 |
|---|---|---|
| 風險 | 使用者不知道有這條線；**這是全站唯一的門檻權威頁，這裡不寫等於哪裡都沒有** | 使用者可能仍然照抄 |
| 憲法對應 | 製造一句新的假話（「這盞燈沒有門檻」），而 `foreign_net` 明明有一份寫好的規格 | §1 允許：把疑義**標註**出來，不靜默通過 |

決定性的理由有三個：

1. **兩種旗標的意義根本不同，「隱藏」會把它們混成一種。**
   - 融資餘額（失準）：**這條線現在正在被使用**，燈真的會亮、真的照這兩個數字判。
     隱藏它 → 使用者看到那盞燈長期偏紅卻找不到原因。**必須顯示。**
   - 外資現貨淨買賣（未接線）：**這條線從來沒有生效過。**
     它是一份規格，不是一個門檻。**顯示，但不能長得跟能用的門檻一樣。**

2. **「照抄」的風險不是靠藏數字解決的，是靠改標題解決的。**
   使用者會照抄，是因為那個數字被放在一個叫「**門檻**」的欄位裡。
   把欄位名改成「門檻（**尚未生效**）」＋ 刪除線 ＋ 一句「**現在不要拿它當操作依據**」，
   照抄的動機就消失了。**藏起來反而會讓人去別的地方找一個更舊的數字。**

3. **資料層早就準備好那句解釋了，是畫面沒有去拿。**
   `unwired_reason` / `degraded_reason` 兩個欄位一直存在，表格七欄一欄都沒帶。
   → **這是漏顯示，不是設計取捨。**

> **分類：修正錯誤。**
> 現行畫面對一份從未生效的規格印出「門檻：紅線 −200 億」，
> 等於替一盞不存在的燈宣稱一條可用的線 —— 那正是 §1 講的
> 「一條全 0 的量能線看起來像有效觀測」。
> **顯示原因、降級標記，是讓畫面回到它本來就該長的樣子。**

## 四、我推薦哪一版

**兩頁我都推薦上面這一版（頁2 圖 A/B/C＋頁5 三段切分＋卡片式）。** 理由，依重要性排序：

**1. 它幾乎不需要新東西。**
橘態、狀態模型、`grid()` 三欄降階、留白不填 0、`unwired_reason` 欄位 —— **全部已經存在**，
而且隔壁的卡片已經在用（熱力圖用橘態、葉2 用降階）。
這一版做的主要是**把已經有的東西接上**，不是發明新機制。
→ 這也代表它的風險最低：憲法 §8.1 第 6 點問「會不會對當前需求太重」，這一版的答案是不會。

**2. 它把「誠實」放在使用者一定會看到的地方，而不是放在補充說明裡。**
現況不是沒有講實話 —— `PE_EMPTY_WHY` 那段文字寫得非常清楚
（「這不是『這些股票都很貴』，是沒有數字」）。**問題是它被一顆綠燈壓在下面。**
這一版沒有增加文字量，只是把燈與標題改成跟那段文字同一個方向。

**3. 它同時修掉一個沒被點名的問題。**
「本次因子：僅基本面四項全過」那句 caption 在**只勾 EPS**（＝預設值）時也是錯的。
不改燈、只改文案的版本會留著它。

**4. 手機版不需要第二套版面。**
三欄網格在窄螢幕自然疊成單欄，這是既有 `grid()` 的行為，
不必寫 breakpoint、不必偵測視窗寬度。

### 我沒有採用的兩個方案

- **只改文案、不改燈**：成本最低，但**沒解決核心問題** ——
  新手看燈不看字。任務問的「怎麼讓部分成功看起來就是部分成功」，
  燈是那個「看起來」的主體。
- **部分成功時整張清單不顯示**：最保守，但會**丟掉真實資訊**。
  那 50 檔是真的按 EPS 百分位排出來的，藏起來是另一種不誠實，
  而且使用者會轉去用更舊的舊分頁。
