**三條跨狀態鐵律**

1. **只有 Error 准用紅色。** 「還沒載入」「沒資料」一律灰 ＋ 不同 glyph 區分（憲法 v3 §02）。
2. **Loading 不得顯示上一輪的值。** 顯示舊值會讓使用者拿舊數字做今天的決定。
3. **狀態徽章與業務燈號不可同時出 emoji。** 卡片同時有「資料狀態」與「業務判讀」兩個頻道時：
   **狀態頻道出 glyph ＋ 中文，業務頻道只出中文**。否則畫面上兩個 🔴 分不出是
   「指標真的很糟」還是「資料抓不到」。

### 1.4 數值呈現規則 — 三者不可混（與狀態分離）

| 顯示 | 語意 | 樣式 | 判定條件 |
|---|---|---|---|
| `0.00` | **正常有效數值**。零是一個觀測值 | 正常文字色，等寬 | 欄位在、值真的是 0 |
| `N/A` | **不適用**。這個標的天生沒有這個概念 | 灰字，**不加圖示** | 例：不配息標的的殖利率 |
| `⚠︎ —` | **缺漏**。本來應該有，這次沒有 | 灰字 ＋ **琥珀色警示圖示** | 來源失敗／筆數不足／欄位空 |

> ⭐ **最容易搞混的一組，畫面上必須看得出差別**：
> - 成交量 `0` ＝ **跌停無量成交，是有效觀測** → 顯示 `0`
> - 成交量 `⚠︎ —` ＝ **來源沒給** → 顯示 `—` ＋ 琥珀
> - 殖利率 `N/A` ＝ **這檔不配息** → 灰字 `N/A`
>
> 三者若都畫成空白或都畫成 0，等於捏造（憲法 §1）。

**狀態與數值是兩個獨立頻道 —— 一個 Normal 卡片裡可以有 `—` 的格子：**

```
┌─ 台積電 2330 ────────────────┐
│ 現價   【1,085.00】          │   ← 有效數值
│ 本益比 【⚠︎ —】               │   ← 同一張卡裡的缺漏格
│ 殖利率 【1.85】               │
│ 🟢 運作中                     │   ← 區塊狀態仍是 Normal
│ 本益比未取得，見佐證          │
└──────────────────────────────┘
```
這**不是** bug：區塊態說的是「這一區有沒有正常運作」，格子說的是「這一格有沒有值」。

## 6. 正式修正提案（本組做不到母法要求的地方）

> 格式：**變更條款／阻礙原因／替代方案／影響評估**。

### 6.1 提案 W-1｜8 種資料狀態 vs 現有狀態模型（**拍板點 A，最高優先**）

**變更條款**
> 母法：「8 種資料狀態：Normal / Loading / Empty / Missing / Partial / Off-Market / N/A / Error」

**阻礙原因（實測）**

台股站已落地 `shared/ui_state.py` **七態**模型，基金站另有 `ui/helpers/render_state.py` **三態**模型。
三套分類**互不相同**。台股七態 vs 母法八態的逐項對照：

| 母法 8 態 | 台股站七態 | 關係 |
|---|---|---|
| Normal | `UI_LIVE` | ✅ 等價 |
| Loading | `UI_LOADING` | ✅ 等價 |
| Empty | `UI_EMPTY` | ✅ 等價 |
| Error | `UI_FAILED` | ✅ 等價 |
| Partial | `UI_DEGRADED` | ⚠️ **不等價**。`degraded` ＝「有值但門檻失去判別力」；Partial ＝「部分欄位有、部分沒有」 |
| Missing | （無對應**狀態**） | ⚠️ 目前是**值級**語彙（`MISS_*` 六種原因） |
| N/A | （無對應**狀態**） | ⚠️ 同上，是 `MISS_*` 的一種 |
| Off-Market | **完全不存在** | 🔴 無資料源，見 §6.4 |
| — | `UI_IDLE`（尚未載入） | 🔴 **母法 8 態沒有它**，但這是憲法 v3 §02 點名的主角 |
| — | `UI_UNWIRED`（未接線） | 🔴 母法 8 態沒有它，但新頁大量使用 |

⇒ **聯集是 10 個狀態，不是 8 個。** 硬壓成 8 個必然要刪掉兩個，而：
- 刪 `idle` → 直接違反憲法 v3 §02（「未點擊載入以灰色說明提示」）
- 刪 `unwired` → 「刻意沒接的功能」會被畫成「故障」或「無資料」，兩者都是假話

**替代方案**

| 方案 | 做法 | 優點 | 缺點 |
|---|---|---|---|
| **甲** | **母法 8 態視為「呈現分類」，底層維持 7 態 + 值級語彙**。`idle` 併入 Normal 前的一個「未載入」呈現、`unwired` 併入 `N/A` 呈現 | 不動既有模型、不動守衛測試、風險最低 | 母法字面上的「8 種」與 code 的態數對不上，日後稽核會反覆問 |
| **乙** | **擴為 10 態**：母法 8 態 ＋ `尚未載入` ＋ `未接線` | 語意最乾淨、每種情況都有專屬說法 | 要改 L0 模型 + CI 守衛 + 兩站；`Off-Market` 仍然無資料源（空殼） |
| **丙** | **嚴格照母法 8 態重寫**，刪 `idle` / `unwired` | 完全符合母法字面 | 🔴 **違反憲法 v3 §02**，且會讓「未接線」畫成紅燈 —— 不建議 |

**★ 總管推薦：方案甲。具體原因三條**
1. 母法列的 8 種**本來就是講「畫面上要分得出來的情況」**，不是講「程式裡要有幾個 enum」。
   甲方案下，畫面上使用者**看得出 8 種差別**（母法的目的達成），而底層不動。
2. 乙方案要改的是 L0 共用模型 + 兩站 + CI 守衛，屬跨站大重構，**成本與這次要交付的東西不成比例**。
3. 丙方案會直接牴觸憲法 v3 §02，且 `Off-Market` 仍是空殼 —— **付了重寫成本卻沒買到那一格**。

**影響評估**
- 選甲：本線框**無須改動**（本文件已按甲寫）。`Off-Market` 那一格仍需 §6.4 拍板。
- 選乙：本線框 §1.3 狀態表要補兩列；台股站 L0 模型 + 基金站三態模型都要改，屬跨站重構，須另走 §8.4 範圍提案。
- 選丙：本線框 §1.3 要刪兩態；且需客戶明示同意牴觸憲法 v3 §02（本組不會自行執行）。

### 6.2 提案 W-2｜「展開佐證」的顆粒度（**拍板點 B**）

**變更條款**
> 母法：「第四層展開觸發器一律是各**區塊**標題右側的『展開佐證』次級文字按鈕」
> 母法：「⛔ 卡片本身點擊不觸發全層展開」

**阻礙原因**
第二層是「3~4 格核心大卡片」，每張卡**自己也有標題**。於是「各區塊」有兩種讀法：
- **讀法一（區塊級）**：L2 整組算一個區塊 → 整頁 3 顆觸發器（L1、L2、L3）
- **讀法二（卡片級）**：每張卡算一個區塊 → 整頁 6~7 顆觸發器

兩種都不違反「卡片本身不可點」（觸發器是卡上的一個文字按鈕，不是整張卡可點）。
**但首屏的按鈕數量差 2 倍以上**，視覺密度差很多。

**替代方案**

| 方案 | 觸發器數量 | 佐證內容 |
|---|---|---|
| **甲｜區塊級** | 每頁 3 顆 | 一個展開區內**分節**寫 3~4 張卡的佐證（本文件 §2.1 的畫法） |
| **乙｜卡片級** | 每頁 6~7 顆 | 每張卡各自展開自己的佐證，展開位置在該卡正下方 |
| **丙｜混合** | L1/L3 區塊級、L2 卡片級 | 卡片各自展開；清單與結論用區塊級 |

**★ 總管推薦：方案甲（區塊級）。具體原因三條**
1. **首屏最乾淨**，符合母法「第一、二層零互動可見」的精神 —— 卡片區塊應該是「一眼看完」，
   每張卡掛一顆按鈕會讓視線在 4 個次級按鈕之間跳。
2. **母法用的字是「區塊」不是「卡片」**，而同一段裡另外用了「卡片」兩字（「卡片本身點擊不觸發」）
   —— 同一段文字裡兩個詞分用，區塊級是較忠實的讀法。
3. **8 種狀態的揭露反而更完整**：一個共用展開區可以並列呈現「A 卡正常、B 卡缺資料、C 卡不適用」，
   讓使用者一次看懂**為什麼同一排卡片長得不一樣** —— 分開展開就看不到這個對比。

**影響評估**
- 選甲：本線框**無須改動**。
- 選乙：本線框每張卡的框線圖要各加一行觸發器；手機版單欄堆疊時按鈕數量會明顯增加。
- 選丙：本線框 §2 各頁的 L2 區塊要改畫。

### 6.3 提案 W-3｜再平衡目標比例的保存（**拍板點 C**）

**變更條款**
> 母法：「含 ETF 交易與再平衡偏離提示動線」

**阻礙原因（實測）**
持股帳本（Google Sheets）的欄位是
`name / ticker / lots / avg_price / updated_at` —— **五欄，沒有「目標比例」**。
再平衡是「實際比例 vs **你想要的**比例」的比較，缺了後者就**算不出偏離**。
現行舊分頁有一個「目標比例%」輸入欄，但它只活在該次瀏覽階段，**不寫回帳本** → 重整即消失。

**替代方案**

| 方案 | 做法 | 保存 | 代價 |
|---|---|---|---|
| **甲｜當場填，不保存** | 維持現況：使用者每次自己填 | ❌ 重整即失 | 零 schema 變更；但每次都要重填，實用性低 |
| **乙｜帳本加一欄** | Google Sheet 持股表新增 `target_pct` 第 6 欄 | ✅ 永久 | **動到客戶的 Sheet schema**；需處理既有列的空值；舊分頁讀取端要相容 |
| **丙｜另開一張設定表** | 新增一個獨立 worksheet 存目標配置 | ✅ 永久 | 不動既有持股表；但多一張表要維護，且要處理「標的在 A 表、目標在 B 表」的對不齊 |

**★ 總管推薦：方案乙（帳本加一欄）。具體原因三條**
1. **甲方案等於這個功能做了也沒人用** —— 每次重整都要重填 4~12 個數字，
   實務上使用者第二次就不會再填了，那這一區永遠停在「狀態 A」。
2. **乙比丙少一個對不齊的失效模式**：目標比例天生是「某一檔的屬性」，
   放在該檔那一列最自然；分成兩張表就會出現「賣掉了但目標還在」「新增了但沒目標」的孤兒列。
3. **加一欄是「加」不是「改」**：既有五欄語意完全不動，舊分頁讀取端只要忽略第 6 欄即可繼續運作，
   風險遠低於改動既有欄位。

**影響評估**
- **這是 schema 變更，且動到客戶的生產資料表** → 依憲法 §-1.5 v3 §03-2 ②，
  **本組不會自行執行，等客戶拍板**。
- 選甲：本線框**無須改動**，但 §4.5 那行「目標比例目前不會被保存」的警語**要永久留著**。
- 選乙：本線框 §4.2 表格不變；§4.5 的警語可移除；需另排一次 ETL（既有列補空值）。
- 選丙：本線框 §4.2 要多畫一個「載入我的目標配置」入口。

### 6.4 提案 W-4｜Off-Market 狀態沒有資料源

**變更條款**
> 母法：「8 種資料狀態：… / **Off-Market** / …」

**阻礙原因（實測）**
- 全 repo **沒有任何 `is_market_open` 之類的函式**。
- `requirements.txt` **沒有任何交易日曆套件**（`pandas_market_calendars` / `exchange_calendars` 皆無），
  且憲法 §4.5 明文記載「**不使用**第三方 trading calendar lib」。
- `shared/roc_calendar.py` 只做民國↔西元**年份**換算，**不是**交易日曆。
- ⇒ 系統**無從判斷「現在是不是盤中」**，也無從判斷某一天是不是交易日（颱風假、補行交易日）。
- 另：基金以每日淨值結算，**天生沒有盤中／盤後的概念** → 這一態在基金站本來就不適用。

**替代方案**

| 方案 | 做法 | 誠實度 | 代價 |
|---|---|---|---|
| **甲｜改為「資料時點揭露」** | 不判斷市場開閉，改為**一律標明這筆資料的歸屬日與性質**（例：`09-13 收盤`） | ✅ 只講知道的事 | Off-Market 不成為獨立狀態，而是**每個狀態都帶的一行時點說明** |
| **乙｜引入交易日曆** | 加裝交易日曆套件或自建台股/美股行事曆 | ✅ 可真正判斷 | 新依賴 + 要維護假日表（颱風假無法預先知道）+ 牴觸憲法 §4.5 既有決定 |
| **丙｜用時鐘粗判** | 用 UTC+8 時間 09:00–13:30 粗略當盤中 | 🔴 **會說謊**：假日、颱風假、休市日都會被說成「盤中」 | 低成本但不誠實 |

**★ 總管推薦：方案甲。具體原因三條**
1. **母法真正要防的是「使用者把收盤價當成即時價」** —— 甲方案用「資料歸屬日＋性質」
   直接解掉這個誤解，而且**每一種狀態都解到**（不只 Off-Market 那一格）。
2. 乙方案要推翻憲法 §4.5 既有決定並新增依賴，**而且颱風假這種臨時休市本來就無法預先知道**
   —— 付了成本仍會有說錯的時候。
3. 丙方案**是本線框最該避免的那種錯誤**：一個看起來有效、實際是猜的狀態標籤（憲法 §1）。

**影響評估**
- 選甲：本線框 §1.3 的第 6 列改為「資料時點揭露」，各頁卡片**加一行時點說明**（本文件已在各卡標示資料日）。母法「8 種」在字面上變成 7 種狀態 + 1 種全域揭露 → **需客戶確認可接受**。
- 選乙：需另案評估依賴與假日表維護，屬跨層變更。

### 6.5 提案 W-5｜本益比「≤0（虧損）」與「來源沒給」目前分不出來

**變更條款**
> 客戶交辦：「本益比取自交易所官方值，PE≤0 目前與『來源沒給』長得一樣——
> 你的線框必須讓這兩者**看得出差別**。」

**阻礙原因（實測）**
取數層對兩者的處置**相同**：都不建立對照關係，畫面端收到的都是「這一檔沒有本益比」。
- PE ≤ 0 → 直接跳過，不放進對照表
- 來源空字串／`'-'` → 轉數值失敗 → 同樣跳過
⇒ **畫面端拿到的資訊量是零，無法區分。** 且取數層**沒有 EPS 這個輸入**，
所以連「是不是虧損」都判斷不了（只知道 PE ≤ 0，不知道是分子還是分母造成的）。

**替代方案**

| 方案 | 做法 | 能分辨？ |
|---|---|---|
| **甲｜現況誠實標註** | 兩者都顯示 `⚠︎ —`，在 L4 佐證區**逐字寫明「這兩種情況目前無法區分」** | ❌ 分不出，但**不騙人** |
| **乙｜改取數層保留標記** | PE ≤ 0 時不跳過，改為保留該檔並標記「本益比為非正值」→ 畫面顯示 `N/A（非正值）`；來源空值顯示 `⚠︎ —` | ✅ 分得出 |
| **丙｜自行改算 PE** | 用近四季 EPS 總和自行計算 | ✅ 且符合母法算式定義 |

**★ 總管推薦：方案乙。具體原因三條**
1. **這是取數層一個「不要提早丟棄資訊」的小改**，不新增資料源、不新增依賴，
   把本來就拿得到的資訊（「來源給了一個非正值」vs「來源什麼都沒給」）保留到畫面端。
2. **丙方案是另一件事**：自算 PE 需要季報 EPS 鏈，而財報有公告延遲與審計修正（憲法 §2.3），
   會引入一整套 point-in-time 對齊問題 —— **比這次要解的問題大很多**，應另案。
3. **甲方案不解決客戶點名的事** —— 客戶明講「必須看得出差別」，甲只是誠實地承認看不出來。
   但在乙落地之前，**甲是唯一不騙人的過渡狀態**，故本線框先按甲畫（§2.2）。

⚠️ **措辭注意**：即使採乙，建議標籤寫「**非正值**」而不是「**虧損**」——
取數層只知道 PE ≤ 0，**不知道**是不是虧損（也可能是來源用 0 當佔位符）。
寫「虧損」是替上游宣稱一件它沒說的事。

**影響評估**
- 選甲：本線框**無須改動**（已按甲畫）；客戶點名的需求**未達成**，需在驗收時明確認知。

### 6.6 提案 W-6｜台股持倉沒有幣別與買入匯率 → 匯兌損益永遠 N/A

**變更條款**
> 客戶已查證：「台股持倉表只有 5 欄，沒有幣別、沒有買入匯率。
> 所以『未實現損益』在台股側算不出匯兌部分。畫面上不得假裝算得出來。」

**阻礙原因（實測，本組複驗一致）**
1. **無幣別欄** → 幣別靠代號後綴推斷（`.TW`/`.TWO` → 台幣，其餘一律美元）。
   該推斷的實作 docstring **自承這是脆弱假設**：使用者少打 `.TW` 會被當美元，金額放大約 32 倍。
2. **無買入匯率欄** → 成本與現值都用**今天同一個即期匯率**換算
   ⇒ 損益是**純價格報酬 × 今日匯率**，**不含匯兌損益**。
3. 歷史事故紀錄（該模組 docstring 逐字）：曾因把原幣金額直接相加造成
   美債 ETF 現值低估 32 倍、股債比 93/7（真值約 30/70）、組合殖利率 12.20%（真值約 3.9%）。

**替代方案**

| 方案 | 做法 | 代價 |
|---|---|---|
| **甲｜維持 N/A（本線框現況）** | 匯兌損益卡**永遠**顯示 `N/A`＋說明「帳本未存買入匯率」 | 零變更；該卡永遠是空的 |
| **乙｜帳本加兩欄** | 新增 `currency` + `fx_at_buy` | 動客戶 Sheet schema；**既有列補不回來**（當初的匯率沒留存）→ 只有新輸入的才算得出 |
| **丙｜沿用基金站做法** | 基金站已有 `currency` + `avg_fx`（**算得出匯兌損益**），台股站比照 | 同乙，但有現成範例可循 |

**★ 總管推薦：方案甲（本階段），並把乙/丙列入下一階段。具體原因三條**
1. **這是本次線框階段的正確答案**：客戶明令「畫面上不得假裝算得出來」，
   甲就是那句話的落地 —— 一格誠實的 `N/A` 勝過一個估出來的數字。
2. **乙/丙無法回溯既有持股**：買入當時的匯率沒有留存，補欄位只對**未來新增**的持股有效。
   ⇒ 就算今天加欄，這張卡在一段時間內**仍然是 N/A**，不會馬上變好看。
3. **與提案 W-3（目標比例加欄）是同一張表** → 若客戶決定動 schema，
   **兩案應該一起做**（一次 ETL，而不是兩次）。

**影響評估**
- 選甲：本線框**無須改動**（已按甲畫，見 §2.5）。
- 選乙/丙：本線框 §2.5「匯兌損益」卡的 8 態表要重寫（目前 7 態標為「不會出現」）；

  （基金站含匯兌、台股站不含）—— **同名不同義，屬憲法 §4.1 級別的陷阱**，建議在兩站都標註。
