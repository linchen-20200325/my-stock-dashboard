## 0. 先講三個我自己查證過的事實（不是轉述）
═══════════════════════════════════════════════════════════════

### 事實 1｜主按鈕根本不在冷啟動的畫面上
`render_page_hold()` 的結構是 `st.tabs([戰情室, 組合設定])`，
表單（含那顆「🚀 跑存股戰情室」）在**第二葉**。
Streamlit 預設打開**第一葉** ⇒ 冷啟動的人看到的是整片灰的戰情室，
**而那顆能救他的按鈕不在畫面上**。
14 段灰字裡確實有一句「到組合設定，按…」，但它埋在每段的第三行。

→ 這不只是「預設值選錯」，是**主要動作被藏在第二個分頁**。

### 事實 2｜「沒讀 Google Sheet」為什麼是 14 遍
不是有人複製貼上 14 次。是 `_idle_note(scope_idle=True)` 這**同一段文字**
被掛到 14 張卡上，每張卡各自 `render_note()` 一次。
我靜態掃出 12 支 `build_*` 會掛它，加上綁定那兩張卡 = 14，
與紅隊實跑的 14 次吻合（兩邊獨立得到同一個數字）。

→ 所以修法不是「刪掉那段字」，是**把它從 14 張卡上拿下來、集中講一次**。

### 事實 3｜指路句壞掉的程度比回報的更嚴重（兩層，不是一層）
`shared/station_specs.py:318` 寫「真要看趨勢請到 🏆 個股組合的『📊 財報趨勢×轉機』區塊」。
- **第一層**：沒有叫「🏆 個股組合」的頁籤。實測 `app.py:730` 是
  `🔬 選股 › 📊 多檔個股比較`；那個區塊本身**存在**（`tab_stock_grp.py:304`
  標題是「📊 財報趨勢 × 轉機（找體質差→變好）」），只是**路名過期**。
- **第二層（回報裡沒有的）**：`app.py:585-605` 顯示新五頁與舊七頁是**互斥**的
  —— 選到新頁時 `st.stop()`，舊七個頁籤**一個都不會渲染**。
  使用者站在頁4，照著指路句去找，**永遠找不到**，因為他得先把左邊側欄
  切回「不使用（用下方原功能）」。**那一步指路句沒講。**

→ 這一頁（以及另外四頁）所有指向舊頁籤的句子，都缺同一個前置步驟。

### 1-C｜「沒讀 Sheet」的灰態：一次講清楚要怎麼講

**規則：一句話只准出現在一個地方。**

| 現在 | 改成 |
|---|---|
| 14 張卡各印一次完整說明（全頁 11,122 字，整片灰） | 頁首狀態條印**一次**完整說明（約 180 字） |
| 每張卡的說明第三行都寫「到組合設定改選項再按一次」 | 狀態條上放**一顆按鈕**直接改完重跑（不用叫人自己走回去） |
| 卡片本身占滿版面 | 卡片摺疊成一份**清單**（上面「這一輪沒讀到」那 12 個名字） |

**但下面這四件事一項都不准跟著消失**（§1）：

| 狀態 | 處置 | 為什麼不能一起摺 |
|---|---|---|
| ⬜ 尚未載入 | **可以**摺成清單 | 12 個「沒叫過」講 12 遍沒有增加資訊 |
| ⛔ 未接線 | **不摺**，永遠可見（放在自己的摺疊區，但那個摺疊區的標題本身永遠在） | 這是「這個功能還沒做」的誠實揭露，跟這一輪讀不讀 Google 無關 |
| 🔴 取得失敗 | **絕對不摺**，各自一張紅卡 ＋ 原始錯誤訊息 | 真故障要看得見。§1.A 第 4 點：真出錯才給紅色 |
| 🟠 門檻已失準 | **不摺**，但貼在它要警告的那張表旁邊 | 見 1-D |

⚠️ 這個設計讓「沒讀 Google Sheet」這件事**比現在更醒目**，不是更不醒目 ——
它從「埋在 14 段一模一樣的灰字的第一行」變成「頁首一塊獨立的說明 ＋ 一顆修好的鈕」。
§1 的要求是「必須讓使用者知道」，不是「必須印 14 遍」。

## 2. 斷點策略表（標的 B）

### 2-A｜先回答那個問題：MAX_COLS=3 在 641–1024px 合不合適？

**不合適 —— 但問題不在那個「3」，在於它現在是「硬的」而不是「自適應的」。**

我從實際 CSS 反推每欄最小寬（算式與依據都列出來，不是拍腦袋）：

| 量到的東西 | 依據 | 值 |
|---|---|---|
| 卡片裡**不能換行**的那一段（狀態標籤 ＋ 訊號標籤兩顆膠囊，`white-space:nowrap`） | `_ui_kit.py::_chip()`：padding 1px 8px、border 1px、font-size 11.5px；最長狀態標籤是「🟠 門檻已失準」 | **169px** |
| 加上卡片左右內距與框線（padding 8px 12px、border 1＋3px） | `render_card()` | **≈ 197px** |
| ⇒ 低於 197px 就**水平溢出**（畫面被推寬、要左右滑） | | |
| 卡片裡最寬的**數字**（24px，例：`+1,234,567　（+12.3%）`） | `render_card()` 的 `font-size:24px` | **≈ 246px** |
| ⇒ 每欄低於 **274px** 時，金額會折成兩行 —— 24px 的數字折行看起來像壞掉 | | |

換算成需要多寬的螢幕（欄距 16px、主容器左右內距 32px）：

| 目標 | 3 欄需要 | 2 欄需要 |
|---|---|---|
| **不溢出** | 655px | 442px |
| **好讀（數字不折行）** | **884px** | 595px |

**兩個結論**：
1. Streamlit 1.59.2 在 **641px** 才停止自動堆疊，但 3 欄要 **655px** 才不溢出
   → **641–655px 是一段必然水平溢出的死區**，沒有任何一段 code 擋得住它。
2. 641–884px（正是**手機橫向 ＋ 平板直向**）用 3 欄，每欄只有 197–274px
   → 這正是使用者截圖看到的那個樣子。**不是排版沒調好，是欄數在這段區間就是錯的。**

### 2-B｜斷點策略表（推薦）

| 大螢幕手機直向 · 小平板直向 | 481–640px | **1** | 全寬 | Streamlit 已自動堆疊，**不必動** |
| **手機橫向 · 平板直向（iPad 768px）** | **641–880px** | **2** | 300–420px | ⚠️ **目前是 3 欄 ⇒ 每欄 197–276px，這就是壞掉的那一段。** 3 個一列時降成 **2＋1**（第三張自己一列、佔滿寬） |
| 平板橫向（iPad 1024px）· 小筆電 | 881–1280px | **3** | 265–400px | 3 欄成立，不降階 |
| 桌機 | > 1280px | **3** | > 400px | **維持 3，不要加到 4** |

**每欄最小寬度的硬底線（寫給實作者的驗收值）**：
- **197px** = 再窄就水平溢出（不可跨越）
- **274px** = 再窄金額就折行（可讀性底線，正常情況要守住）

### 2-C｜為什麼「> 1280px 也維持 3 欄」

`MAX_COLS = 3` 這個上限**是對的，不要動它**。它擋掉的是
「`_grid(cards, 7)` 一行開 7 欄」那種失效模式（`tab_today.py` 的註解記著這件事）。
一列超過 3 個東西，人就不會橫向比較了，只會逐個讀 —— 那就不需要排成一列。
**要改的是「窄的時候能不能少於 3」，不是「寬的時候能不能多於 3」。**

### 2-D｜怎麼做到（三個修法，全部屬「修正錯誤」）

| # | 改動 | 性質 | 理由 |
|---|---|---|---|
| B1 | 加一段媒體查詢：641–880px 時讓一列 3 欄**折成 2＋1** | **修正錯誤** | 規格寫的是「**3 欄自適應**網格」。現在它在 700px 不自適應、只是擠 —— 是實作沒做到那三個字。**`MAX_COLS` 一個字都不用改**，也不必偵測螢幕寬（Streamlit 讀不到），純 CSS 就夠。 |
| B2 | 卡片頂端那一排膠囊改成**可換行**（膠囊自己仍 nowrap，但整排可以折第二行） | **修正錯誤** | 現在那一排是硬的 169px，是水平溢出的**唯一**來源。膠囊折行完全可讀；整頁被推寬要左右滑不可讀。 |
| B3 | 24px 的數字改成**可隨欄寬縮**（下限 18px） | **修正錯誤** | 讓 274px 那條可讀線往下移到 ~210px，等於幫 641–880px 這一段多買一層保險。 |
| B4 | 戰情表的燈條（`.dsl-strip`，nowrap）包進**自己的橫向捲動框** | **修正錯誤** | 同一個檔案裡已經有 `.dsl-scroll{overflow-x:auto}` 這個現成做法 —— 讓**表格自己捲**，不要讓**整頁**捲。 |

⚠️ B1 會讓客戶在平板上看到不一樣的排列，所以我仍然把它放進這份草稿等拍板 ——
即使我判定它是「修正錯誤」。依 A-8 標註 (c)：「這算 bug 還是改設計」的判定權在內部，
所以**寧可多送一次拍板，不要少送**。

**第一批（我建議這次就做）—— 全部是「修正錯誤」，不改版面結構**

「按了唯一的按鈕卻看到 14 遍『沒讀』」這個最傷的問題（A2 一項就解掉）。

- A3 冷啟動改成目錄式

理由：這一批才是真正把「冷啟動第一屏」變好看的部分，但它動到版面，
依 v3 §03-2 ① 必須先有這份線框、由客戶拍板。

### 為什麼不推薦另外兩種做法

**❌ 只改預設值就收工。**
預設值改對之後，「只看市場」那條路仍然會印 14 遍。
選那條路的人變少了，但**踩到的人受的傷一樣重**，而且更難被發現。

**❌ 直接把那 14 張灰卡刪掉。**
會一起刪掉「⛔ 未接線」那 4 項的誠實揭露 —— 那不是載入狀態，是
「這個功能還沒做」。刪掉它就是 §1 的掩蓋。所以我的做法是**依狀態分流**
（⬜ 摺、⛔ 不摺、🔴 絕不摺），不是一律刪。
