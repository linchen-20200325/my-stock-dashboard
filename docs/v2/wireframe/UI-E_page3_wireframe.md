### 事實 1｜⚠️ 最嚴重：財報只抓到一半時，畫面會把「沒資料」講成「這家公司很爛」

我用合成輸入實跑了真正的計算函式（不是讀 code 推測），結果：

```
輸入：資產負債表有、現金流量表有、【損益表整段沒抓到】
       （這三張表是三個獨立請求，只有前兩張進錯誤閘門，第三張失敗不算錯誤）

畫面會顯示 ──
  基本面（健康度）  38 / 100 · C 級
                    「🟡 有明顯改善空間，需謹慎評估」
                    不及格項目：100-100-10、本業獲利
  毛利率            0.0% · 普通
  營業利益率        0.0% · 【本業虧損】     ← 這句是憑空生出來的
  安全邊際          0.0% · 抗震尚可
```

真相是「損益表沒拿到」，畫面講的是「這家公司本業在虧錢、體質 C 級」。
**沒有任何一格標示成缺資料。**

這正是客戶核准的線框第 824 格點名要修掉的那個病
（線框原文：「把『沒有資料』講成『這是爛生意』」）——
線框的修法補在**顯示層**（缺值查表落灰），但**上游把缺值換算成 0 再送下來**，
顯示層拿到的是一個「看起來完全正常的 0.0%」，攔不住。

⚠️ 誠實邊界：這是**結構上可達**的情形（三張表各自獨立抓、只有兩張進錯誤閘門），
我用合成輸入重現了它；**我沒有在正式站上觀察到它實際發生的頻率**。

### 事實 2｜冷啟動有 476 字是同一段話貼四遍（佔全頁 26.7%）

冷啟動全頁 1,780 字（我重數了一次，去掉空白換行剛好 1,780，與紅隊一致）。
其中「尚未載入任何分析 / 為什麼沒有… / 去哪補…」這一整段
**一字不差出現 4 次**（判型結果、健康度、估值、籌碼各一次），共 476 字。

**而客戶核准的線框並沒有要求這樣做。** 線框原文寫的是：

```
葉1-A 判決卡  greyCells:[['健康度','⬜ 未載入'],['估值','⬜ 未載入'],['籌碼','⬜ 未載入']]
葉1-A 明細    grey:{now:'⬜ 尚未載入任何明細', why:'…', where:'…'}
```

→ 線框要的是：**三張判決卡只寫「⬜ 未載入」四個字，那段完整說明只出現在「明細」那一區、只出現一次。**
**現況才是偏離線框的那一邊。**

### 事實 3｜主按鈕在手機上看不到

手機 375px 時欄位會自動堆疊成一欄（這是 Streamlit 自己的行為，641px 以下都堆疊）。
於是表單在手機上的實際順序是：
代碼框 → 判型下拉 → 期間下拉 → 一句說明 → 一句說明 → MA5 → MA20 → MA60 → MA100 →
MA120 → MA240 → **然後才是「🔍 載入完整分析」按鈕**。

粗估堆完超過 700px，而 iPhone 可視高度約 560px
→ **打開這一頁，看不到那顆要按的按鈕。**
（這與頁4 稽核到的是同一個病；欄寬與斷點數字沿用該組實測，我沒有重跑。）

### 事實 4｜6 個均線 checkbox 唯一的作用是改一行字

我把整個檔案掃過，`mas`（勾了哪些均線）**全檔只被讀一次**，讀在
「判型結果」卡的一行灰字：`期間 / 均線　250 交易日 · MA20、MA100`。
除此之外**沒有任何地方用到它** —— 因為要用它的那張 K 線圖還沒接上。

而 **MA20 與 MA100 預設是勾起來的**。
畫面沒有任何地方告訴使用者「這兩條是預設值、不是我們推薦的」——
它看起來就像系統幫你選好的設定。

「期間」下拉（120 / 250 / 500）也差不多：它唯一真正做的事是決定
「籌碼那一格去載入多長的日線」，但**籌碼的判讀窗固定是近 20 天**（由上游決定），
所以 250 改 500 **不會改變任何一個結論**，只會讓籌碼卡多一行
「本輪載入 500 個交易日的日線」。

### 事實 5｜「位階」這面向，有一份資料現在就抓回來了，但畫面沒有用

查一檔個股時，系統已經連同財報一起把 **KD（短線高低檔）** 抓回來了
（`kd_state`：K 值、D 值、高檔鈍化／低檔鈍化／頂背離／底背離、黃金／死亡交叉）。
**畫面完全沒有顯示它。** 要用它 → **零額外等待、零額外請求**。

## 2. 頂部體檢區 —— 規格（客戶第 1 題）
═══════════════════════════════════════════════════════════════

### 2-A｜先講一個我不做的事：**不做綜合分數**

客戶要「直覺體檢」，最直覺的做法是給一個「這檔幾分」。**我不建議做，而且建議明文禁止。**
理由：基本、籌碼、位階三者量的是**完全不同的東西**（一個看財報、一個看誰在買、
一個看價位高低），把它們平均成一個數字，等於發明一把沒有任何出處的尺；
而且只要其中一項缺資料，那個綜合分就會**默默地變成一個假的數字**（事實 1 就是這樣來的）。

**改用「數得出來的東西」當直覺入口**：一行分母。

```
🔬 2330 台積電 · 個股          3 項體檢：可判 2 項 · 資料不足 1 項
```

這一行不是新的判斷，只是把三張卡各自的狀態數一數。
（這個做法是「🚦 今天」頁已經在用、線框指名要抄到全站的那個樣板。）

### 2-B｜三個面向各自長什麼樣

每一格都是三層，**由上到下**：

```
① 一句人話判決（大字，直接用上游已經寫好的那句話，本頁不自己編）
② 支撐它的一個數字（中字）
③ 一句「這數字是什麼意思」（小字，新手用）
```

#### ① 基本 —— 「這家公司體質如何」

| 項目 | 內容 |
|---|---|
| 大字（判決） | 直接用上游寫好的總結句，例：「體質良好，六大面向多數過關」 |
| 中字（數字） | `78 / 100 · B 級` |
| 小字（新手） | 「滿分 100，看的是十項財報體檢：現金夠不夠用、收錢快不快、本業有沒有賺、負債會不會太重。**不看股價。**」 |
| 補充列 | 沒過關的項目名（例：收現速度、盈餘含金量）；上一季到這一季是變好還是變差 |
| 資料來源 | `src/services/dividend_station_service.py::fetch_metrics(code,'stock')` → `_fetch_stock_metrics` → `src/services/financial_health_engine.py::no_ai_overall_verdict`（`mj_score_pct` / `mj_grade` / `mj_headline` / `mj_fail_items` / `trend_verdict`） |
| 門檻住哪 | `shared/financial_health_thresholds.py`（`FH_*` 19 個） |
| **拿不到時** | 灰色。「**這一檔的財報體檢分數算不出來**」＋為什麼＋去哪補。**不寫 0 分、不寫任何等第。** |
| **⚠️ 必加的新守衛** | 財報只回來一半（拿不到營業收入）時 → **一律灰態**，不得出分數、不得出「本業虧損」。判斷依據：`營業收入(千) <= 0`。（事實 1；屬**修正錯誤**） |

#### ② 籌碼 —— 「這 20 天誰在買」

| 項目 | 內容 |
|---|---|
| 大字（判決） | 上游給的訊號中文：「大戶吸籌」／「大戶倒貨」／「籌碼發散」 |
| 中字（數字） | `集中度 1.83%` |
| 小字（新手） | 「最近 20 個交易日，外資＋投信買超的張數，約等於這 20 天總成交量的 1.8%。**數字越大代表買盤越集中在法人手上。**」 |
| 補充列 | 連續性（20 天裡有幾天是法人買超）／**單日爆量檢查**（三態：有異常／判過了沒異常／判不出來） |
| 資料來源 | `src/services/stock_chips_service.py::get_chips_readout(code, days=)` → `shared/macro_compute.py::analyze_20d_chips_from_df`；爆量徽章 → `src/compute/risk/inst_sanity.py::flag_latest_inst_outlier_from_df` |
| 門檻住哪 | `shared/signal_thresholds.py::INST_NET_OUTLIER_VOLUME_RATIO` |
| **拿不到時** | 分三種、**不可混**：還沒按載入＝灰；日線抓不到＝紅；日線有了但法人欄缺／全 0＝灰「資料缺漏」。**不得填 0% 集中度**（0% 的意思是「買賣剛好抵銷」，那是結論不是缺值）。 |
| 現況 | ✅ 這三態現在就已經做對了，**照抄不動**。 |

#### ③ 位階 —— 「現在這個價位算高還是低」

⚠️ 這一格有**兩把尺**，量的不是同一件事，**必須分開講、不准合成一個結論**。

| 項目 | 內容 |
|---|---|
| 大字（判決·主尺） | 上游給的字面：「甜甜價」／「高殖利率」／「合理」／「昂貴」／「超貴」 |
| 中字（數字） | `殖利率 5.42%`，並附三檔目標價（便宜價 / 合理價 / 昂貴價） |
| 小字（新手） | 「用**配息**回推：同樣的股利，股價越低、殖利率越高就越便宜。**這把尺只適用會配息的公司。**」 |
| 副標（副尺·**本次新增**） | 「短線：高檔鈍化」／「低檔鈍化」／「頂背離」／「底背離」／「無特別訊號」＋ `K 82 · D 76` |
| 副標小字 | 「這是**短線**的高低檔，看的是最近幾天的漲跌強弱，**跟上面那把「貴不貴」不是同一件事**，兩個可以同時是紅的或同時是綠的。」 |
| 主尺來源 | `src/compute/strategy/v5_modules.py::calc_dividend_yield_357`，輸入 `src/services/valuation_service.py::get_stock_dividends` |
| 主尺門檻 | `shared/thresholds.py::YIELD_HIGH / YIELD_MID / YIELD_LOW`（7% / 5% / 3%） |
| 副尺來源 | `fetch_metrics` 回傳的 `kd_state` → `src/compute/strategy/tech_indicators.py::analyze_kd_state` ＋ `kd_cross_state`（**資料現在就已經抓回來了，畫面沒用**） |
| 副尺門檻 | `shared/signal_thresholds.py::KD_OVERBOUGHT_LEVEL / KD_OVERSOLD_LEVEL / KD_PASSIVATION_DAYS` |
| **主尺拿不到時** | 灰。**兩種原因分開講**：(a)「這一檔近 5 年沒有配息，這套尺本來就不適用它 —— 重按幾次都一樣」；(b)「配息資料這一輪三個來源都沒給，可以重按一次試試」。**絕不填 0%**（0% 會被同一組門檻判成「超貴」）。 |
| **副尺拿不到時** | 灰。「歷史天數不夠算短線高低檔（剛上市或長期停牌會這樣）」。 |
| **兩把尺都拿不到** | 整格灰，**不得只因為有副尺就把卡片畫成綠的**。 |

**為什麼要加副尺？** 因為主尺對**不配息的成長股**永遠是「不適用」——
那些股票的位階格會永遠空白，而客戶問的正是「新手看不看得懂」。
副尺讓那些股票至少有一句誠實的話可說，而且**零額外等待**。

**為什麼不合成？** 一檔股票可以同時是「以配息看很貴」和「短線在低檔」——
合成一個「位階分數」會把這個矛盾抹平，而那個矛盾正是使用者該看到的東西。

### 2-C｜ETF 的頂部三格（不套用個股那三個面向）

客戶的問題是「查一檔**個股**時」，所以 基本／籌碼／位階 是**個股**的規格。
ETF 維持線框已核准的三格（折溢價／配息／追蹤·同儕），只加同一套新手化三層：

| 格 | 大字（判決） | 中字 | 小字（新手） |
|---|---|---|---|
| 折溢價 | 「貼近淨值」／「溢價偏高」 | `+0.12%` | 「你買的價格跟它真正的身價差多少。**正的太多＝買貴了。**」 |
| 配息 | 「年化 5.8%」 | `5.80%` | 「照最近一年的配息推算，一年大概領回本金的百分之幾。」 |
| 追蹤／同儕 | 「同類前段班」 | `近 12 月分位 0.18` | 「跟同類型的其他 ETF 比，0 是最強、1 是最弱。」 |

⚠️ **ETF 沒有「籌碼」這一格，而且不可以留白讓人以為是壞了。**
如果客戶希望 ETF 也有籌碼，那是**未接線**（資料存在、本站沒取），
不是「不適用」—— 兩者在畫面上要長得不一樣。本次我**不建議**加，理由是
它要再發一輪三大法人的請求，而 ETF 判斷的重點在折溢價與費用，不在單日法人進出。

### 6-B｜逐項怎麼收

**① 技術指標** —— 現在**唯一拿得到的是 KD**。

  → 這樣「技術指標」在畫面上只佔 **2 行**，而不是 7 個空標題。

**② 三率穿透** —— 第二層，常駐 3 格，**不摺疊**。
- 現況只有 毛利率／營業利益率／安全邊際 三格。

  - 資料：淨利率與 ROE **本來就在同一份回傳裡**（`Net_Margin` / `ROE`），零額外請求。
  - 線框原文也預留了這個位置：「第 2 排留給後續補齊的淨利率 / ROE」。
  - 性質：**改變設計**（動到看得見的三格內容）→ 需拍板。
- 「穿透」那一層（展開才看）：營收／毛利／營業利益／稅後淨利的**原始金額**，
  讓使用者能自己驗算「58.2% 是怎麼來的」。

**③ 籌碼明細** —— **不另開區塊，全部收在「籌碼」那張卡裡**（現況就是這樣，照留）。

- 卡內補充列：連續性、單日爆量檢查
- 這樣籌碼在畫面上只佔 **一張卡**，而不是一張卡＋一個明細區塊。

### 7-B｜我的建議（三項，全部是「推薦」不是選項）

**建議 1｜均線 6 顆 checkbox：從表單搬到「未接線」卡裡，並全部停用、預設全部不勾。**

- **不刪掉**：客戶核准的線框第 811 格明文寫了「均線　MA20 · MA100 已勾」，

- **不能留現況**：預設勾著 = 系統推薦的假象。本次硬約束第 3 條明文禁止
  「未接線的控制項長得像可用的推薦設定」。
- **搬到未接線卡裡**是唯一同時滿足兩者的做法：控制項還在（線框沒被推翻），
  但它跟「K 線還沒接上」那句話**貼在一起**，因果一眼可見，而且**停用（灰、點不動）**
  比留在表單裡可以點卻沒反應誠實得多。
- **預設改成全部不勾**：線框寫「MA20 · MA100 已勾」描述的是**接上之後**的樣子；
  在還沒接上的狀態把它畫成「已勾」，是線框沒有預料到的情況。
  → 我判定為**修正錯誤**，但因為它會改變畫面上看得到的預設值，**仍然送客戶拍板**。

**建議 2｜期間下拉：停用，改由系統固定用 250 個交易日。**

- 它現在唯一的可見效果，是籌碼卡裡多一行「本輪載入 500 個交易日的日線」——
  對新手是純噪音，對任何結論零影響。
- 留一個「可以選、但選了不會變」的下拉，本身就是本次要清掉的那種東西。
- 若客戶希望保留可調（例如未來 K 線接上後要看更長），
  **第二方案**是保留但改標籤成「載入多長的日線（不影響判斷結果）」——
  **我不推薦**，因為它把一句免責聲明變成永久的畫面噪音。
- 性質：**改變設計**（移除一個看得見的控制項）→ 需拍板。

**建議 3｜「還原 K」那句 caption：留著，但搬到 K 線那張未接線卡。**
它描述的是還沒接上的那張圖，放在表單裡等於替一個不存在的圖背書。
性質：**修正錯誤**。

### 7-C｜為什麼不建議「直接把 K 線接上」

接上 K 線要讓現在住在舊「🔬 個股」分頁的那幾段程式能被重複掛載
（元件識別碼要能加前綴、取數要改走中介層、載入開關要由呼叫端提供）——
那是**跨多檔案、會改變資料流**的工程，不是這一輪線框能決定的範圍。
**在它接上之前，讓控制項停用並說清楚，比讓它假裝能用誠實。**
