## S2 單檔入口：代碼、判型、期間、MA 勾選

**現況（FACT）**：一個 `st.form`（代碼＋判型＋期間＋6 個 MA 勾選＋一顆送出鈕）；送出鈕寫「已套用值」，**這個鍵的存在就是整個單檔結果的 gate**（widget 當下值與已套用值分家，沒按送出不取數）。MA 勾選**沒有任何計算會讀它**（頁面自己揭露：「均線的選擇目前沒有東西會用到」）。

```
BEFORE（查一檔葉）                           AFTER
┌ ① 代碼  ② 期間 / K 線  ③ 均線 ┐ 3 欄       ┌ 🔎 [輸入代碼（例：2330 或 00878）____] [🔍 載入完整分析] ┐
│ [代碼]   [期間▾]       MA5  MA20  MA60 │      │ ▸ 進階選項（判型・期間・均線）          ← 預設收合       │
│ [判型▾]  還原價說明     MA100 MA120 MA240│     │   ├ 判型：[自動判型（系統判）▾]                         │
│ [🔍 載入完整分析]                       │      │   ├ 期間（交易日）：[250▾]  K 線一律用還原價            │
│ 取數接線揭露…（長段工程字樣）          │      │   └ 均線：☐MA5 ☑MA20 ☐MA60 ☑MA100 ☐MA120 ☐MA240       │
└─────────────────────────────────────────┘     │     ⓘ 均線勾選目前只會顯示，不影響任何結論             │
                                                └──────────────────────────────────────────────────────────┘
手機：代碼框與按鈕上下堆疊；進階選項內各控制項單欄；仍在同一個 st.form（一顆送出鈕）
```

- **維持 form＋送出鈕**：進階選項（摺疊）**放在 form 內**，仍只有一顆送出鈕，gate 語意不變（INFERENCE：expander 內 widget 可在 form 內，實作時以測試釘住；未在沙箱實跑）。
- **MA 勾選：保留並照實揭露「僅回顯，不影響結論」**。**移除它也是 UI 變更（欄位減少），由客戶決定要不要拿掉**；本草稿不替客戶移除。
- 搜尋框 placeholder：wireframe 寫「輸入代碼或名稱」，但**名稱搜尋目前未接**（S9）；推薦只寫「輸入代碼」，不承諾名稱搜尋。

**推薦＋理由**：進階選項收合。理由：90% 使用情境只需代碼；判型／期間／MA 是少用控制項，收合後手機第一屏乾淨；保留 MA 並揭露＝不減功能、不騙人。**風險**：控制項被收合後可發現性降低 → 摺疊標題寫明內容「判型・期間・均線」。

## S6 候選表「點一列展開第三區」互動

**gate 語意（兩個方案共同）**：使用者的選取動作＝「使用者要求」，**寫入與搜尋框送出相同的已套用鍵**（`SS_APPLIED_TICKER` 同一個鍵）；**冷啟動零取數**；第三區在鍵存在前只顯示灰字引導。Streamlit 版本 floor 以 `requirements.txt` 現行宣告為準（撰寫時 `>=1.56.0,<1.60.0`；不在此寫死）。

| | **方案 A（推薦）：表下方「選一檔＋查看此檔」** | 方案 B：dataframe 點列（`on_select`） |
|---|---|---|
| 互動 | 表格下一行：`[選擇標的 ▾（列出本表代碼＋名稱）] [🔍 查看此檔]`；按鈕寫 gate，第三區展開 | 直接點表格某一列→第三區展開（最貼近 wireframe 文字「點一列」） |
| 好處 | 明確的「使用者要求」動作；手機好點；與現有 form／gate 寫法一致；沙箱可用 AppTest 驗 | 少一步；符合 wireframe 文字 |
| 風險 | 與 wireframe「點一列」文字不同（需客戶同意）；多一個控制項 | 選取狀態在 rerun／換排序／重新選股後可能殘留或失效；手機點列精準度；AppTest 對 dataframe 選取支援**未驗**；選取即觸發整頁 rerun |
| 版面變動 | +1 列控制項（在表下方） | 0 新增控制項 |

**推薦：A**。理由：與既有 gate 寫法一致、風險最低、沙箱可驗；等實機驗證後再評估升級為 B。

| 估值 | **當日本益比（PE）**，≤0 視為缺值（既有說明）；**欄尾小字標口徑與資料日**（見下） | `⬜` |

- **估值口徑不同要寫明（避免被讀成同一個數）**：候選表「估值」＝當日本益比（`valuation_service`）；第三區「估值（357）」＝存股估值區間（殖利率口徑，沿用個股健康度那一輪的現價）。表下一行灰字：「估值欄是當日本益比（資料日 ○○○○-○○-○○）；第三區的估值是另一種算法（殖利率口徑），兩者不同、不能互相驗證。」資料日若取不到→「資料日：⬜ 未提供」（INFERENCE：本益比資料日目前是否有欄位**未驗**）。

- **推薦＋理由**：照表。理由：全部既有來源、零新算法；籌碼只對展開那檔取避免 300 檔逐一抓。**風險**：籌碼欄多數列是「未取」，使用者可能以為壞掉 → 欄頭小字「點選一檔後才會取」。
