## 4. 資料契約與分母

- 來源清單優先沿用 `src/data/core/data_registry.py`、`shared/data_categories.py`、`src/services/data_registry_scanner.py`、`src/services/data_registry_summary_service.py`、正式 health canonical；各自「靜態宣告／掃描寫入／唯讀呈現」角色不同，不應合併或直接由 UI 發取數請求。
- 每列至少規劃：`item_id`（正式 ID 若已有）、項目名稱、群組、`capability`、`data_state`、`source`、`as_of`、`retrieved_at`、`last_success`、`freshness`、`failure_reason_scrubbed`、`proxy_or_fallback`、`affected_consumers`、`evidence_ref`。**這是 UI 需要清單，不聲稱 canonical 已有全部欄位**；缺欄標 DATA_CONTRACT_GAP，禁止臨時新增或用現在時間填補。
- Capability（已接線／未接線）與 Data State（OK/Missing/Stale/Unavailable/Not Evaluated）分軸。尚未接線列的 Data State 為「不適用」，**不能算成失敗或未評估**。執行成功、API 200、parse 成功、有效資料日期是不同事實，不能單一綠燈代表全部。
- 「抓不到」總表至少區分：尚未實作、認證/配額不足、來源連不上、格式解析失敗、空回應、日期過期、經裁示未評估、規格不支援；原因碼須由現有證據支持，不能猜。
- 敏感資訊：禁止 token、帳戶、Sheet ID 全碼、原始 exception/traceback、env vars、私有路徑；所有使用者可見錯誤都先 scrub。
- 資料頁不直接控制取數或正式定義；重跑/通知/匯出功能只有通過授權與權限 Gate 才啟用，避免另一個寫入途徑。
- 靠 Provider/Source 定時刷新不代表首頁在使用時一定讀到當下有效資料；顯示**來源資料時點**和**最後嘗試時點**差異。
