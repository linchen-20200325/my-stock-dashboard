### 3.2 發布腳本的保護設計（FACT，讀 `scripts/publish_data_pr.py`）

- **只判實質變更才發 PR**；JSON 忽略揮發鍵（更新時間等）。
- **合併規則 fail-closed**：同一日期的既有列，舊值非空而新值為空，或兩邊皆有值但不同 → 腳本中止（不寫入、不提交、不推送）；**舊空→新有值才採新值**（這就是 §2.1 台股 11-10 成交量被補上的原因）；forward-test 凍結帳本任何差異皆中止。
- **不 force、不 rebase、不碰 workflow、不推 main、不啟用自動合併**；腳本內有明文攔截 `gh pr merge`。
- **人工審閱聲明**：PR 本文固定寫「未見 `ui2-browser-gate` 綠燈（且 head SHA 與本 PR 相符）前不得合併」「未經人工審閱不得合併。本 PR 未啟用 auto-merge」。
- **內建 token 建立的 PR 不一定觸發 required check**：腳本檔頭自承「需由有權限者以原生 pull_request 事件觸發（Close→Reopen、Update branch 等）；實際行為以 GitHub 為準，沙箱無法驗證」。現況證據：三個 PR 的 check runs 皆為 0（2026-11-12 文件組讀取）。
- **分支每日把 main 合併進來（不 rebase）**：因此三個 PR 現在各有 3 個提交，且相對 main「落後」。

- 速度：0 批。
- Token／成本：0；無外部費用。
- 可逆性：完全可逆（隨時改選）。

**方案 B｜先授權一次「唯讀外部對帳」，結果出來再裁示**
