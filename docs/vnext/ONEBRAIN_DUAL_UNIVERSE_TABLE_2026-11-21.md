# OneBrain 雙母體表（持有全集 vs 可評分全集）— 2026-11-21

> **依據**：`docs/DECISIONS.md` DEC-218（客戶裁示 #1199 comment 7054425559：Q1=B、Q2=(a)）與 DEC-215。
> **性質**：語意示意，**不是 schema、不是欄位定義、不是實作規格**。下文名詞（含總管 #7054409431 舉例的 `selected_holdings_total` 等）只用來說明語意，**欄位命名與 schema 均未授權**。
> **用途只有一個**：避免把 Q1=B「持有部位全集」讀成「持有＝可評分（held=scoreable）」。單組撰寫，非 QA PASS。

## 1. 兩個母體

| | 持有全集（DEC-218 Q1=B） | 可評分全集（DEC-215） |
|---|---|---|
| 回答的問題 | 選定組合裡有哪些持有部位？有沒有漏算？ | 哪些標的經正式資格判準後可被評分？ |
| 起點 | 「👤 我的」目前選定的**單一本組合**的持有部位（ETF 與個股皆屬範圍） | 正式資格判準之後、Top-N／市場條件篩選之前 |
| 不計入 | 觀察清單；同一本 Sheet 的其他組合；SA headless cron 多 Sheet 合併母體 | 依該判準（判準本身＝NOT VERIFIED，待另行決策） |
| 現有代用名詞 | 無 | **不得**以 `actions_total_eligible`、`scoring_eligible`、`_is_scorable` 冒充 |

**兩者必須分開計數。** 兩者的集合關係（子集／交集）未定義＝NV；不得用其中一個的計數充當另一個。

## 2. 持有全集內的狀態（互斥）

先看整體來源狀態：

- **UNKNOWN**：無法取得來源、讀取失敗、未選定組合 → **所有總量為 None**，不做列分類，**不得顯示 0**。（UNKNOWN 只在整體層級＝撰寫組讀法，依決策單 #7054362484 §2 矩陣「UNK＝整體無法判定記 None」；裁示原文未限定層級。）

整體來源可用時，選定組合中的每一個來源持有列**恰好**落在下列一類：

| 狀態 | 意思 | 例 |
|---|---|---|
| **IN** | 在持有全集，且已評估 | 評估成功、資料符合新鮮度／PIT／品質／適用規則 Gate |
| **IN-U** | 在持有全集，但未能評估（須附原因） | 張數或均價空白；行情取數失敗；下游評估失敗；過期資料（見下） |
| **EX** | 不納入，但須可回報數量與原因 | 來源持有列部位欄（代號／張數／均價）的無效值：NaN、±inf、非數值、≤0、空代號 |

- **過期（STALE）是標記，不是一種狀態**：過期列可留在持有全集並標 STALE／資料日，但**不因有過期數值就自動算 IN**。客戶已排除「過期算已評估並標註」。在何種條件下過期列可算 IN 尚未決定；在決定前不得歸 IN（撰寫組讀法，非客戶原文）。
- 取數或評估失敗**不得**讓部位從持有全集消失（只能是 IN-U，不能變成不存在）。行情取數得到 NaN 等屬下游評估失敗 → IN-U，不是 EX。
- ⚠️ #1242 P2（`docs/vnext/ONEBRAIN_UPSTREAM_EXCLUSION_POINTS_CONTRACT_EVIDENCE_2026-11-21.md`）：預設解析把空白格讀成 0 而落入 ≤0。G-X1 須先分清「空白」與「≤0」，否則應為 IN-U 的空白列會被誤歸 EX。

## 3. 基本等式（整體來源可用時；計數單位待定，見第 4 節）

```
選定組合的來源持有列 = IN + IN-U + EX
持有全集              = IN + IN-U
已評估                = IN
未能評估              = IN-U（逐原因揭露）
不納入                = EX（逐原因揭露）
整體 UNKNOWN 時        → 以上全部為 None（不是 0）
```

- 分母不得由截斷後的輸出（Top-N、`station_rows`、`holdings_rows`、`ranked`）倒推。
- EX 的原因鍵與 L1 剔除計數屬 G-X1，**尚未授權實作**；目前不能宣稱上式已可量測。

## 4. 重複代號（聚合粒度未定）

- 須揭露來源重複列數與代號；**不得**默默去重、**不得**覆寫持有批次、**不得**讓同一母體重複灌水。
- 同代號不同購買批次要算「1 個部位」還是「N 列」，以及張數／均價怎麼合併：**未授權**；若尚無既有核准契約，待明確技術契約（撰寫時單組 grep 未找到既有批次合併公式，非窮舉）。
- 決策單 B 欄的「以代號去重」與「重複代號合併為 1 員＋揭露」預設**不生效**（DEC-218 §一 6）。因此第 3 節等式的計數單位（列或代號）**目前未定**。
