## 2. 殼的形式候選

### 2.0 共通前提（三案皆同）

| 項目 | 內容 |
|---|---|
| 預設狀態 | 「不使用（用下方原功能）」，畫面＝舊 7 頁籤，與現在一樣（`app.py::_IA_NAV_OFF`，radio `index=0`，`FACT`） |
| 選到之前一行不跑 | 沒選任何方向時，不載入任何新版頁（現行守衛 `tests/test_ia_v2_sidebar_nav.py::TestNothingRunsUntilYouPick`，`FACT`）；殼不得破壞這點 |
| 切回舊版 | 維持「側欄『🆕 新版戰情室（試用中）』選『不使用（用下方原功能）』」（`page_me.py::SWITCH_BACK_TEXT` 現行寫法，`FACT`） |
| 方向順序 | 📊 → 🎯 → ⚡ → 🛡️ → 👤 → 🩺（客戶 Stage C 與 `PROJECT_RULES.md` 19.2 列舉順序） |
| 未建置標記 | 文字＋圖示「⬜」，不只靠顏色（19.8） |
| 手機版 | 單欄；側欄需先展開才看得到導覽（`INFERENCE`：Streamlit 預設行為，**未實機操作**） |

導覽步數的算法：**從「預設（不使用）」到達某一頁需要的點擊數**；電腦版側欄常駐；手機版另加 1 次「展開側欄」（`INFERENCE`）。

### 2.1 形式 (a)｜側欄單層清單，六向當小標題、葉縮排

一條側欄清單，六個方向當小標題，每個頁縮排在方向底下，一次點到位。

**電腦版**
```
┌ 側欄 ─────────────────────┐ ┌ 主畫面 ──────────────────────┐
│ 🆕 新版戰情室（試用中）     │ │ 📍 位置：🎯 標的 › 🔬 查一檔   │
│ ◉ 不使用（用下方原功能）    │ │ ───────────────────────────── │
│ 📊 大盤                    │ │  （被選到的那一頁，內容不動）   │
│    ○ 📊 大盤               │ │                              │
│    ○ 🚦 今天               │ │                              │
│ 🎯 標的                    │ │                              │
│    ○ 🔍 找標的             │ │                              │
│    ○ 🔬 查一檔             │ │                              │
│ ⚡ 行動                    │ │                              │
│    ○ ⚡ 行動 ⬜            │ │                              │
│ 🛡️ 持股                   │ │                              │
│    ○ 💼 我的持股           │ │                              │
│ 👤 我的                    │ │                              │
│    ○ 👤 我的               │ │                              │
│ 🩺 資料中心                 │ │                              │
│    ○ 📖 憑什麼             │ │                              │
│    ○ 🩺 資料中心 ⬜        │ │                              │
│ ⬜ ＝ 尚未建置              │ │                              │
└───────────────────────────┘ └──────────────────────────────┘
```

**手機版（單欄）**
```
[☰ 展開側欄]                    ← 先點這個（+1）
┌ 側欄抽屜 ──────────────┐
│ ◉ 不使用 / 📊 / 🚦 …    │   ← 同上清單，共 6 標題＋9 項＋「不使用」
└────────────────────────┘
選完後：
📍 位置：🎯 標的 › 🔬 查一檔
（該頁內容，單欄）
```

| 項目 | 內容 |
|---|---|
| 到任一現行頁的點擊數 | 電腦 1 次；手機 2 次（+展開側欄） |
| 清單長度 | 6 標題＋9 選項＋「不使用」＝約 16 行；手機要捲動（`INFERENCE`） |
| 對 `app.py`／測試的影響（依 D0 §5.3，只描述） | 現行 radio 與 `_IA_NAV_OPTIONS` 逐字斷言（`(_IA_NAV_OFF, *_IA_PAGE_LABELS.values())`）必然要改；`_sb_ia_page` 仍可維持單一鍵；`_IA_VIEWS` 與 `PAGE_LABELS` 的 set 對帳要重新定義（佔位頁不是 view）；改動面中等 |
| 技術不確定 | Streamlit 單一 radio **不能放不可選的小標題**（`INFERENCE`，未驗）；若不行，小標題只能改成選項文字前綴（例：「📊 大盤 › 🚦 今天」），視覺上就不再是「標題＋縮排」 |

| 方案 | 優點 | 缺點 | 風險 |
|---|---|---|---|
| (a) 單層清單 | 一次點到位；現行 radio 結構最接近、改動最小；頁名不重複就能直接指路 | 之後每多一個葉，清單就變長，「導覽」實際上會一直變動，與「之後不再改導覽」的精神有張力；單葉方向（🛡️、👤）名稱重複；手機清單長 | 六向只剩視覺小標題，最上層導覽不是真的六個選項；未建置項混在清單裡，容易被讀成缺陷 |

### 2.2 形式 (b)｜側欄兩層：先選方向，再選該方向底下的頁

第一層永遠是六個方向（加「不使用」）；選到有兩個以上頁的方向，才在下方多出第二層。

**電腦版**
```
┌ 側欄 ─────────────────────┐ ┌ 主畫面 ──────────────────────┐
│ 🆕 新版戰情室（試用中）     │ │ 📍 位置：🎯 標的 › 🔬 查一檔   │
│ ◉ 不使用（用下方原功能）    │ │ ───────────────────────────── │
│ ○ 📊 大盤                  │ │  （被選到的那一頁，內容不動）   │
│ ○ 🎯 標的       ← 已選     │ │                              │
│ ○ ⚡ 行動 ⬜               │ │                              │
│ ○ 🛡️ 持股                 │ │                              │
│ ○ 👤 我的                  │ │                              │
│ ○ 🩺 資料中心               │ │                              │
│ ──────────────             │ │                              │
│ 🎯 標的 底下：              │ │                              │
│ ○ 🔍 找標的  ◉ 🔬 查一檔    │ │                              │
│ ──────────────             │ │                              │
│ ⬜ ＝ 尚未建置              │ │                              │
│ ⓘ 驗收完成後，這區會取代上方頁籤 │ │                          │
└───────────────────────────┘ └──────────────────────────────┘
```
（「ⓘ 驗收完成後，這區會取代上方頁籤」是現行側欄說明，原樣保留；`app.py` `FACT`。）

**手機版（單欄）**
```
[☰ 展開側欄]                    ← +1
┌ 側欄抽屜 ──────────────┐
│ ◉ 不使用                │
│ ○ 📊 ○ 🎯 ○ ⚡⬜ ○ 🛡️ ○ 👤 ○ 🩺 │  ← 第一層（7 項）
│ 🎯 標的 底下：           │
│ ○ 🔍 找標的 ◉ 🔬 查一檔  │  ← 第二層（僅多葉方向才出現）
└────────────────────────┘
主畫面：📍 位置：🎯 標的 › 🔬 查一檔 ＋ 該頁內容
```

| 項目 | 內容 |
|---|---|
| 到任一現行頁的點擊數（電腦） | 📊 大盤 1｜🚦 今天 2｜🔍 找標的 1｜🔬 查一檔 2｜💼 我的持股 1｜👤 我的 1｜📖 憑什麼 1｜⚡ 佔位 1｜🩺 資料中心 佔位 2（手機各 +1） |
| 方向預設落點 | 進入方向時落在該方向**第一個葉**；葉的排序規則＝已建的在前、未建的在後（讓進入方向時優先看到可用的頁）；回到曾看過的方向時，回到該方向上次看的葉（僅限本次使用，重新整理即消失） |
| 對 `app.py`／測試的影響（依 D0 §5.3，只描述） | 需要第二個導覽狀態（目前 `_sb_ia_page` 字串「只准出現在 `app.py`、位置須恰為 `[("app.py",1)]`」的守衛要改）；`_IA_NAV_OPTIONS` 逐字斷言要改；`_IA_VIEWS[` 只准 1 次、`_VIEW_MODULES` 寫死 7 個、`st.tabs` 恰 7 個等斷言需同步擴充並**獨立 QA**；改動面三案中最大 |
| 技術不確定 | 方向切換後，第二層殘留選擇如何處理；程式在 rerun 中寫入導覽鍵是否可行**未確認**（D0 §5.4，repo 無此用法） |

| 方案 | 優點 | 缺點 | 風險 |
|---|---|---|---|
| (b) 側欄兩層 | 最上層**永遠只有六個方向**，之後新增或合併葉，只動第二層，上層不變，最符合「導覽一次定案」；單葉方向沒有多餘的第二層；「不使用」維持在最上面且為預設，切回舊版句子**一字不用改** | 三個頁要點兩次（🚦 今天、🔬 查一檔、🩺 資料中心 佔位）；要維護兩個連動的控制項；指路句要多帶方向（見 §5） | 實作與守衛測試改動面最大；方向切換後第二層狀態處理不好，可能停在不屬於該方向的頁（內部技術自決，須獨立 QA） |

### 2.4 三案比較與總管推薦

| 面向 | (a) 單層清單 | (b) 側欄兩層 | (c) 頂部方向列 |
|---|---|---|---|
| 最上層固定為六向 | 否（清單隨葉增加） | **是** | 是 |
| 到頁最多點擊數（電腦） | 1 | 2 | 3 |
| 切回舊版句子是否要改 | 不用 | **不用** | 要改 |
| 預設仍為「不使用」 | 是 | **是** | 是（但要多一步才進新版） |
| 手機單欄 | 清單長，需捲動 | 兩段短清單 | 方向列換行，效果未驗 |
| 對現行 `app.py`／測試改動面 | 中 | **大** | 大 |
| 與「導覽一次定案」精神 | 有張力 | **最吻合** | 吻合 |
| 與 2026-09-08 已拍板取向 | 一致 | 一致 | 相反 |

**總管推薦：(b) 側欄兩層。**（草稿提案，**不是已選**，待客戶裁示。）

具體原因：
1. 客戶要的是「導覽停留長期穩定」（19.2）。(b) 的最上層**永遠是六個方向**，之後 🎯 合頁、⚡／🩺 長出內容，只改第二層，上層不會再變；(a) 的清單每長一個葉就變一次。
2. 切回舊版的步驟與現行**完全相同**（「不使用」仍是最上面、預設的選項），不用改任何已寫給客戶的指路文字。
3. 沿用側欄入口，與客戶 2026-09-08 的已拍板取向一致。

**誠實揭露 (b) 的代價**（客戶選前請看）：
- 🚦 今天、🔬 查一檔、🩺 資料中心 佔位頁各要多點一次（2 次 vs 1 次）。
- 要維護兩個連動的選單，是三案中對 `app.py` 與守衛測試改動最大的（D2 工作量與出錯面最大，須獨立 QA）。
- 指路句要多帶一層方向名（見 §5），句子會變長。
- 全部步數與手機表現都是讀碼推論，**未實機操作**。

## 7. 客戶回覆格式

請用一句話回答，三件事各一個詞：

> **「D1 採〈a／b／c〉｜線框〈核准／退回／指定修改處〉｜佔位頁文案〈同意／修改〉」**

- 全部照推薦：「D1 採 b｜線框 核准｜佔位頁文案 同意」

- 改選：「D1 採 a｜線框 核准｜佔位頁文案 同意」（我們會重出 (a) 的差異圖後再送核准一次，因為 (a) 的 8 個畫面態導覽控制項不同）
