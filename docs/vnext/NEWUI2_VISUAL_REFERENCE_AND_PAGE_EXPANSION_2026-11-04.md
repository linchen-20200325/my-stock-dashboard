> 客戶在本對話提供一張「市場／標的／持股／設定」四面板設計參考圖，表示很喜歡，請盡量朝這方向執行；隨後補充「如果四個頁面不夠，可以多加頁面」。這是新的設計方向核准，不表示示意圖的行情、Risk Cap、OneBrain 結論、資產數據、規則或登入功能已核准為正式事實。

## 2. 四頁是核心，不是硬上限（客戶新增方向）

既有四個入口仍為：市場、標的、持股、我的。新增頁可行，**但不得把新增頁數當成必須達成的目標**。與舊文件固定「不得第五頁」相衝突的部分應標示 SUPERSEDED，不能據此阻止合理擴充；其他資訊架構、資料護欄繼續有效。

新增頁之前，必須先比較三條可行路徑：

| 路線 | 適用情況 | 風險 |
|---|---|---|
| A. 原頁精簡區塊／子標籤 | 同一使用者任務下僅展示不同層次資訊 | 可能拉長單頁 |
| B. 次層功能頁（從原頁明確進入） | 獨立流程但不常用，不該佔常駐主導航 | 需返回／深連結／狀態保留規格 |
| C. 新增第五或更多主頁 | 高頻、獨立任務，與四頁不同責任且現有導覽不易完成 | 會增加主選單與手機操作負擔 |

決策依序看：使用者任務清楚／資料與投資語意正確／原頁有無重複／手機可操作性／速度與 Token。可新增主頁的方向示例包括「全球比較」、「研究」、「資料健康度」等，**都是候選，尚未指定要新增哪一頁**；不得自動把『資料健康度』變成第五頁（目前仍定位在『我的』）。

每一個新頁須先出完整手機與桌機線框、導覽入口與返回、資料來源與 evidence mapping、功能 parity、測試影響、必要 Gate。新頁不得複製另一套 canonical、Rule、System Action、Risk Cap 或 Digest。當新頁並非原有授權明列的施工項目時，仍先交 ChatGPT／客戶設計驗收。

## 3. 自由選擇比較圖與重複圖表整併（設計方向，不授權接線）

- 客戶先前表示希望比較圖能自由選擇，並指出大圖／小圖重複。建議先規劃「主要可選比較圖＋有不同價值的少量小圖／數值卡」，保留不重複的風險／產業／市場廣度等獨立分析。
- 交互項候選：選比較標的、期間 3M／6M／1Y／3Y、同基準日 base=100、原始值／標準化呈現（要先逐指標證實適用性）。台股、S&P500、NASDAQ、SOX、MSCI World、MSCI EM 等只是資料候選；沒有正式 canonical 或授權時顯示 disabled／尚未提供。
- VIX、殖利率、利差、DXY 不可直接與股票指數按同單位疊圖；須拆圖、分類或依已核准的比較口徑才可使用；不得任意雙軸。
- 比較圖不因使用者選擇而重算新的買賣建議；期間、source、as_of、frequency、base、missing 策略與清楚 SPEC 必須逐圖定義。
- 此項是 UX/IA 規劃需求，不授權新 API、額外資料取得、改公式、改主要圖表資料契約。使用者所見其他 Streamlit 市場與趨勢截圖不能當成 New UI2 已完成的實作證據。

## 4. 不可折損的既有正式規格

1. 新 UI2 human UI 精簡，但 Evidence、provenance、Missing 和完整 headless Decision Digest 不能因此刪減。VM 保留不代表 Digest 已有，coverage 須另驗。
2. Risk Cap／System Action／OneBrain／估值目標價與所有決策門檻，只能引用正式 deterministic rules／已核准來源；示意圖的所有數值、字樣、RuleID 均非授權。
3. 資料健康度仍依 P6：Data State 五態和 Capability 分兩欄，Level 3 masked，未接線誠實註記。頁面擴充前不改其已核准落點。
4. 手機抽屜、Google 登入殼／真 Auth 分開；桌機左 rail 保留。不可恢復被 Streamlit 管理浮層遮擋的底部選單作唯一主導航。
5. 保留原先已核准草稿的已實作行為及測試；視覺參考圖不能默默取消現有功能或更改第一屏 CTA、Regime／Action 順序。

## 7. 客戶再次確認的兩條獨立驗收主線（2026-11-04）

> 客戶：「UI設計我想以這為模板為主，但內容部份以完整的給Onebrian，我們說好了 UI簡化，但Onebrian需要吃全部資料給出建議」；並再次確認「沒錯，這也是我們之前討論過的」。**本段重申既有雙投影原則，並指定視覺參考優先，不是授權啟用 OneBrain runtime。**

### 驗收 A：視覺呈現／人類操作

- 以客戶上傳的四頁儀表板圖片為**主要視覺模板**，以已核准 New UI2 資訊架構和後出的手機抽屜決策為約束；保留卡片式、Chart-first、結論／風險／正式行動權威優先、短來源與資料日。
- 可簡化 UI 上顯示的區塊、合併重複大小圖、以少量關鍵圖卡取代原始表；但不能把畫面隱藏誤當資料刪除。手機與桌機分別做視覺驗收，不能以文字線框或 AppTest 取代實際畫面。
- 此圖是**外觀模板**，非圖中範例數值、RuleID、Risk Cap 或 AI 結論的事實來源。完整圖像目前仍是聊天附件，未落成 repo 圖片資產；若需 pixel parity，需另外取得可用圖檔並完成版型 Gate。

### 驗收 B：完整資料與 OneBrain 決策證據（不可被 UI 縮減）

- **正式 Data／Validation／Deterministic／Risk Cap／System Action／Complete Evidence → UI ViewModel 與 headless Decision Digest 兩個獨立投影**。OneBrain 只能透過完整、可追溯且已核准的 Decision Digest 消費正式證據，不能只讀 UI 卡片、選中期間、當前頁面、Top N、FAKE 資料、渲染文字或本次視覺模板。
- 所謂「全部資料」指**所有已獲核准、在正式資料層可取得且經過驗證的決策相關欄位、規則結果、完整反證、source/as_of/freshness、Missing/Stale/Unavailable/Not Evaluated 與 coverage 限制**；並不代表將未驗 raw blob、credential、隱私敏感內容或無關資料一股腦傳送給模型。
- OneBrain 目標是基於完整證據提供具體、可追溯的投資分析與建議；但**不得自創事實、補缺值、另立 Rule／Risk Cap／System Action、越權買賣、將未評估當安全**。正式 Action Authority 不可被 LLM 覆蓋；資料不齊時要明示「無法判定」與阻塞理由，而非強行給買賣動作。
- **VM 完整 ≠ Digest 完整**。當前已知位階完整說明、16 項明細、個股基本面及估值等 Digest coverage 尚未驗／存在缺口；必須在 OneBrain 啟用前建立 `canonical field → normalized evidence → Digest field → OneBrain consumer` 的逐項 coverage matrix、缺欄 Gate 與回歸測試。禁止因 UI 視覺驗收 PASS 就宣稱 OneBrain 資料已備齊。
- 兩條驗收必須**分別 PASS**。A 的修訂不准移除 B 的資料，B 的補齊不准把 raw Evidence 重新塞回主要 Human UI；後續每批應分別報告 Visual Fidelity 與 Digest Coverage 的已驗、缺口、不可判定。
